# challenges

**自分が抱えている技術課題**を書き溜め、それに対する解決策をクラウドエージェントが調べる。
**週1回（土）8:00 (JST)** 実行。情報収集系と違い、課題はそう速く増えないため週次。

```
challenges.md      ← 人間が書く。エージェントは読むだけ
solutions/
  YYYY-MM-DD.md    ← エージェントが書く調査結果
```

## なぜファイルを分けているか

`challenges.md` を**エージェントに編集させない**。人間の記録をAIに書き換えさせると、
自分が何を書いたのか分からなくなり、記録としての価値が落ちる。
エージェントは読むだけで、調べた結果は `solutions/` に別途書く。
解決済みへの更新は人間が判断して行う。

## 書き方

```markdown
## [未解決] タイトル

- **状況** — 何をしようとして、何が起きているか
- **試したこと** — 既に試して駄目だったこと（同じ提案を避けるため）
- **欲しいもの** — どうなれば解決と言えるか
```

解決したら `[未解決]` を `[解決]` に変え、**何で解決したかを1行追記する**。
エージェントは `[解決]` の項目を調査対象から外す。

公開リポジトリなので、業務の課題は**社名・製品名・アカウント構成などの固有名詞を避けて**書く。
技術的な性質だけ書けば調査には十分足りる。
