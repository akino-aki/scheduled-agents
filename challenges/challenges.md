## [未解決] 録画中に「手が止まっている時間」を自動で扱いたい

- **状況** — OBS を Claude Code の skill から操作して開発作業を録画している。
  作業の合図で開始・終了の合図で停止しているが、**手が止まっている時間がそのまま録画され続ける**。
  止め忘れると 2.5GB/時 でディスクを消費する。逆に、作業中と思って止めたら再開が必要になったこともある。
- **試したこと** — 開始・停止を明示的な合図でのみ操作する運用。手が止まった時間の扱いは未対応。
- **欲しいもの** — 無操作が続いたら自動で一時停止する、または後編集で切りやすい印が自動で残る仕組み。
  OBS 側の機能でできるのか、外部から入力を検知して制御する必要があるのかを知りたい。

## [未解決] AIが生成した問題を、AI自身に検証させてから公開したい

- **状況** — 水平思考クイズ（いわゆる「ウミガメのスープ」）の Web アプリを個人開発している。
  出題の登録から公開までを全自動にしたい。ただし**問題として成立しているか**（正解に到達可能か、
  情報が不足していないか、複数解釈が生まれないか）を人間が確認しないと公開できない状態。
- **試したこと** — 判定役の AI に解かせる案を検討中。実装には至っていない。
- **欲しいもの** — 「AIが解けたかどうか」を合格条件にする設計の妥当性を知りたい。
  解けてしまう＝簡単すぎる、解けない＝不備がある、の切り分けをどう作るか。
  同種の「生成物をAIに検証させる」パイプラインの実例が知りたい。

## [未解決] レビューの指摘品質を、経験差に依存させずに揃えたい

- **状況** — IaC（AWS CDK）で構成されたマルチアカウント環境の開発で、
  経験の浅いメンバーのプルリクエストに対するレビュー品質が、レビュアーによってばらつく。
  コードの差分を見るだけでは**実際に何が変わるのか**が分かりにくいことが原因の一つ。
- **試したこと** — 合成後のテンプレートを差分比較して、意図しない変更を見つける方法を検討中。
- **欲しいもの** — IaC のレビューで「差分の意味」を機械的に提示する手法・ツールの実例。
  CI に組み込んでレビュー時に自動で提示するところまで持っていきたい。

## [解決] 情報収集エージェントの実行時間が観点を増やすほど伸びる

- **状況** — 1つのエージェントに複数観点の調査をさせていたため、観点を足すほど時間がかかっていた。
  どの観点で情報が取れなかったのかも分からなかった。
- **解決** — 2026-08-05、**観点ごとに routine を分割**した。
  観点ごとに独立したセッションで走るため実行時間が分散し、頻度と時刻も個別に調整できるようになった。
