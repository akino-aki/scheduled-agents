# scheduled-agents

Claude Code のクラウドエージェント（routines）を定期実行し、その成果物を溜めているリポジトリ。
**収集も要約も分類も人間はやっていない。** ここにあるファイルは全てスケジュール実行されたエージェントが書いている。

## 動いているもの

| ディレクトリ | 内容 | 頻度 | 実行時刻 (JST) |
|---|---|---|---|
| [`ai-news/`](ai-news/) | Claude Code を中心とした AI の最新情報・使いこなし | 毎日 | 7:12 |
| [`loop-engineering/`](loop-engineering/) | ループエンジニアリング（AIを自律ループで回す設計手法） | 毎日 | 7:40 |

実行時刻をずらしているのは、同じリポジトリへの push が衝突しないようにするため。

## なぜクラウドで動かしているのか

最初は Windows のタスクスケジューラで毎朝 7:12 に実行していた。**動かなかった。**

計測して分かったこと:

```
PC最終起動        2026-08-05 19:33:57
タスク実行         2026-08-05 19:38:06   ← 予定は 7:12
StartWhenAvailable True                  ← 取り逃した分を後で実行する設定
```

朝7時にPCの電源が入っていない。`StartWhenAvailable` によって起動の4分後に遅延実行されていただけで、
**「朝、最新情報が手元にある」という当初の目的は一度も達成されていなかった。**
成功扱い（終了コード 0）でログが残るため、動いているつもりになっていた。

ローカルマシンの電源状態に依存する設計が原因だったので、実行をクラウドへ移した。
現在は PC の状態に関わらず実行され、朝はスマートフォンから結果を読んでいる。

## 設計上の判断

- **観点ごとに routine を分けた** — 1つのエージェントに全観点を持たせると実行時間が伸び、
  どの観点で情報が取れなかったのかも分からなくなる。分ければ個別に頻度と時刻を調整できる
- **過去のファイルは書き換えさせない** — エージェントが触ってよいのは当日分の新規ファイルだけ。
  過去の記録を後から改変されると、何がいつ分かったのかを追えなくなる
- **重複を除外させる** — 直近のファイルを読ませてから収集させ、同じ情報が毎日並ぶのを防いでいる
- **URL を推測で書かせない** — 実在確認できたものだけを載せる制約をプロンプトに入れている
- **件数を埋めさせない** — 新しい情報が無い日は「該当なし」と書かせる。
  毎日同じ件数が並ぶより、無い日が分かるほうが情報として正しい

## プロンプトについて

各エージェントのプロンプトは routine の設定側に置いてあり、このリポジトリには含まれていない。
リポジトリはあくまで成果物の置き場。
