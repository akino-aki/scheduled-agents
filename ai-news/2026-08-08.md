# 2026-08-08

- **[公式][実務] Claude Code v2.1.224 — サンドボックス内でAWS SigV4署名を自動的に再署名（`credentials.awsPairs`/`sigv4`）** — https://code.claude.com/docs/en/sandboxing#re-sign-aws-requests
  - **何が起きたか**: 8/7リリースのv2.1.224で、サンドボックス設定に `sandbox.credentials.awsPairs` と `sigv4` が追加された。`AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` をマスクしても、egressプロキシがSigV4署名を検出して実値で再署名し、サンドボックス化されたBashからのAWS APIコールがそのまま通るようになった。
  - **なぜ注目されているか**: これまでサンドボックス内でAWSキーをマスクすると、署名がプレースホルダ値で計算されるためAWS側で署名エラーになり、「鍵を隠す」と「AWSを叩かせる」が両立しなかった。今回プロキシ側の再署名対応が入り、この制約が解消された。
  - **使いどころ**: マルチアカウント環境でサンドボックス化したBashにCDK/AWS CLIを叩かせているなら、`awsPairs`設定でキー漏洩リスクを下げつつ自動化を続けられる。ユーザー設定・管理設定・`--settings`からのみ有効で、プロジェクト設定（`.claude/settings.json`）に書いても効かない点は要注意。

- **[公式][企画] Claude Code v2.1.224 — セッション間メッセージング（`SendMessage`/`ListAgents`）が追加** — https://code.claude.com/docs/en/cross-session-messaging
  - **何が起きたか**: 同一マシン上、またはRemote Control経由の別マシン上にある自分のClaude Codeセッション同士が、`SendMessage`でテキストメッセージを送り合えるようになった（macOS/Linuxのみ、v2.1.224以降）。宛先は`ListAgents`（`/list-agents`）で探索する。
  - **なぜ注目されているか**: 複数のworktreeやターミナルでセッションを並列に走らせていても、これまで変更内容を別セッションに伝えるには人間がコピペするしかなかった。1つのセッションの発見や完了を他セッションへ自動で伝搬できる経路が公式に用意された形。
  - **使いどころ**: 今すぐ必須ではないが、並列worktreeで進めているサブエージェント同士に変更点を自動連携させたり、「複数のClaude Codeが会話しながら開発を進める」デモとしてYouTube企画にそのまま使える題材。

- **[公式] Claude Code セルフホスト環境がTeam/Enterprise向けパブリックベータで公開** — https://code.claude.com/docs/en/self-hosted-environments
  - **何が起きたか**: 8/6付で、クラウドセッション（claude.ai・モバイル/デスクトップアプリ・`claude --cloud`・scheduled routine経由）を自社ネットワーク内の「ランナー」上で実行できる「セルフホスト環境」がTeam/Enterpriseプラン向けにパブリックベータ公開された。モデル推論自体はAnthropicのAPIに送られ、Bedrock等へのルーティングは不可。
  - **なぜ注目されているか**: これまでクラウドセッションは常にAnthropic管理インフラ上で実行され、社内VPC内のDBやサービスに直接アクセスさせることはできなかった。ランナーを自社ネットワーク内に置くことで、外部公開していない社内リソースに対してもクラウドセッションから安全にアクセスできるようになった。
  - **使いどころ**: 個人開発やTeam/Enterprise未契約のソロ利用では今すぐ不要。将来チームでCDK/ECSのVPC内リソースへ scheduled routine からアクセスさせたい要求が出たら選択肢に入る。
