- **[実務][企画] Claude Code v2.1.286 — プロジェクト/ユーザーskillに`verify`という名前のものがあると、コミット直前に自動実行される規約を追加（docs-only・tests-onlyのコミットは除く）** — https://github.com/anthropics/claude-code/releases/tag/v2.1.286
  - **何が起きたか**: v2.1.286のリリースノートに「Improved commit guidance: when your project or user skills include one named `verify`, Claude is now told to run it right before committing, except for docs-only and tests-only commits」と明記された。
  - **なぜ注目されているか**: 従来この種の「コミット前チェック」はPreToolUse hookを自作して実装するのが一般的だったが、今回は「`verify`という名前のskillを置くだけ」という命名規約ベースの仕組みが公式に追加された形。hookより設定が軽く、skillとして書けるぶんAIが中身を理解した上で呼び出す点も異なる。
  - **使いどころ**: skill/hook/routineを自作する関心が強いなら、プロジェクト直下に`verify`skill（lint・型チェック・テスト実行などをまとめたもの）を置いておくと、Claude Codeがコミット前に自動で走らせてくれる。経験の浅いメンバーのPRレビュー品質を揃えたい文脈でも、「コミット前に最低限のチェックを強制する」仕組みをフック実装なしで導入できる選択肢として試す価値がある。

- **[実務] AWS公式`aws-core`プラグインの`aws-containers`スキル — CloudWatch LogsのAction Logs配信失敗アラームが、実在しないメトリクス名`ForwardingErrors`を指していたため永久に発火しない不具合を修正（9/30マージ, PR #371）** — https://github.com/aws/agent-toolkit-for-aws/pull/371
  - **何が起きたか**: `aws-containers`スキルのセキュリティ強化ガイダンスが、CloudWatchアラームの対象として`ForwardingErrors`というメトリクスを推奨していたが、これは`AWS/Logs`名前空間に実在しないメトリクスだった。このガイダンス通りに作成したアラームは`INSUFFICIENT_DATA`のまま一度も発火しない。PRでは実在する`DeliveryErrors`・`DeliveryThrottling`への修正が`plugins/aws-core`・`skills/core-skills`両方の`references/action-logs.md`に適用された。
  - **なぜ注目されているか**: 「アラームが一度も発火しない」状態は、アラームが存在しないより気づきにくく危険という典型例。AIが提案するIaC/監視設定コードが、存在しないメトリクス名を尤もらしく書いてしまう具体例として、CDKで監視設定をレビューする際の注意点になる。
  - **使いどころ**: `aws-core`プラグインのガイダンスを参考にECS環境のログ配信失敗アラームをCDKで組んだことがあるなら、`ForwardingErrors`を指定していないか確認し、`DeliveryErrors`/`DeliveryThrottling`に置き換える。経験の浅いメンバーのPRレビューでも、「AIが提案したメトリクス名がAWS公式ドキュメントに実在するか」を確認項目に加える具体例として使える。
