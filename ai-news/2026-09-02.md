- **[公式][実務] Claude Code v2.1.257 — auto modeに「Containment Escape」ルールを追加、クラウドメタデータ資格情報の取得・egress回避・テナント越境アクセスを自動承認しないように** — https://github.com/anthropics/claude-code/releases/tag/v2.1.257
  - **何が起きたか**: 9/1リリースのv2.1.257で、auto modeの安全性分類器にContainment Escapeルールが追加された。クラウドのメタデータエンドポイントからの資格情報取得、egress回避、テナント境界を越えるアクセスは、環境側が「想定内」と明示しない限り自動承認されなくなった。
  - **なぜ注目されているか**: クラウドのインスタンスメタデータエンドポイント（AWSなら169.254.169.254）から一時的なIAM認証情報を取得する手口は、SSRF攻撃で認証情報を窃取する定番パターンとして広く知られている。auto modeはこれまでファイルの大量削除や認証情報ファイルへの書き込みなど直接的に危険な操作はブロック対象にしてきたが、メタデータ取得のような間接的に認証情報を持ち出せる経路への専用ルールは今回追加された形。
  - **使いどころ**: AWSマルチアカウント環境でauto modeを使っているなら、この種の経路が自動承認されなくなったことでガードが一段強くなる。ただし「環境側でexpectedとマークしない限り」という条件付きなので、CDK/ECSの正当な処理でメタデータアクセスが必要な場面があるなら、`/permissions`のAuto modeタブ（8/27既報）で挙動を確認しておくとよい。

- **[公式][実務] Claude Code v2.1.257 — プラグインの宣言パスがシンボリックリンク経由でディレクトリ外を読めていた不具合を修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.257
  - **何が起きたか**: 同v2.1.257で、プラグインがcommand/agent/skill/hooksなどの宣言パスをシンボリックリンクにしておくことで、プラグイン自身のディレクトリ外のファイルを読めてしまう不具合が修正された。該当パスがシンボリックリンクの場合はエラーで拒否されるようになった。
  - **なぜ注目されているか**: 「許可した範囲の外へ読み書きが漏れる」シンボリックリンク系の穴は8/29・8/30付ダイジェストで既報の通り、ファイルツールやWorkflowの`scriptPath`、Grep/Globなど複数の経路で今月繰り返し見つかってきたテーマ。今回はそのうちプラグインの宣言パスという、チーム外・社外から共有されたプラグインを導入する際に狙われやすい経路への対処になる。
  - **使いどころ**: マルチアカウント環境でチーム外や社外のプラグインを共有・導入する運用をしているなら、直接手を入れる機能ではないがバージョンを上げておくのが対策になる。経験の浅いメンバーがプラグインを追加する際のレビュー観点としても「宣言パスがシンボリックリンクでないか」を頭の片隅に置ける。

- **[公式][実務] Claude Code v2.1.257 — Bashの権限チェックで、zshの`[[ ]]`条件式の解釈違いと、deny ruleがリダイレクト・別名の読み取りコマンドをすり抜ける不具合を修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.257
  - **何が起きたか**: 同v2.1.257で2件の権限チェック不具合が修正された。①zshがbashと異なる解釈をする`[[ ]]`条件式を自動承認してしまっていたものが、承認プロンプトを出すように変更。②`Read()`/`Edit()`のdeny ruleが`< file`のようなリダイレクトや`tac`・`egrep`などの読み取りコマンドには適用されていなかったものが、引数・リダイレクト対象のどちらかに一致すれば拒否するように変更。
  - **なぜ注目されているか**: BashツールはmacOSなど多くの環境で実際にはユーザーのログインシェル（zshであることが多い）を起動しており、bashと文法解釈が異なる場面でルールが想定通り効かないと以前から報告されていた。deny ruleがリダイレクトや別名の読み取りコマンドをすり抜ける問題も同系統の以前からの報告で、8/26付ダイジェストで既報の「ワイルドカードの位置」警告と合わせ、Bash許可・拒否ルールの抜け穴を塞ぐ改善が今月複数回に分けて続いている。
  - **使いどころ**: 経験の浅いメンバーがsettings.jsonにBash許可・拒否ルールを書く場面のレビュー観点がさらに一つ増える。「zshで動く前提でルールを書けているか」「deny ruleはリダイレクトや別コマンド名もすり抜けないか」をチェックリストに追加できる。

- **[公式][実務] Claude Code v2.1.257 — `CLAUDE_CODE_SUBAGENT_MODEL_FORCE`を追加、全サブエージェントのモデルを個別指定より優先して強制上書きするオプションが復活** — https://github.com/anthropics/claude-code/releases/tag/v2.1.257
  - **何が起きたか**: 同v2.1.257で環境変数`CLAUDE_CODE_SUBAGENT_MODEL_FORCE`が追加された。これを設定すると`CLAUDE_CODE_SUBAGENT_MODEL`（未設定ならメインモデル）が、エージェント定義の`model:`や起動時の個別指定を無視して全サブエージェントに強制適用される。
  - **なぜ注目されているか**: 8/30付ダイジェストで既報の通り、v2.1.251で`CLAUDE_CODE_SUBAGENT_MODEL`の挙動は「全サブエージェントを問答無用で上書き」から「未指定時のデフォルト」に変更され、エージェント定義側の`model:`が優先されるようになっていた。今回はその変更後も「やはり全サブエージェントを強制的に揃えたい」場面向けに、旧来の強制上書き挙動を別の環境変数として切り出す形で残された。
  - **使いどころ**: コスト上限のためにサブエージェントのモデルを一律で安価なものに揃えたい場面では`CLAUDE_CODE_SUBAGENT_MODEL_FORCE`を使い、CDK/ECSレビュー用など個別に強いモデルを使わせたいサブエージェントがあるときは設定しない、という使い分けができる。
