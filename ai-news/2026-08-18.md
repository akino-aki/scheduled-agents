- **[公式][実務][企画] Claude Code v2.1.234 — 使用量上限リセット後にセッションを自動継続（デフォルトON）** — https://github.com/anthropics/claude-code/releases/tag/v2.1.234
  - **何が起きたか**: 8/17リリースのv2.1.234で、claude.aiの使用量上限に達してセッションが一時停止した場合、上限がリセットされた時点で自動的に作業を再開するようになった。デフォルトで有効、`/config`の「Continue automatically at usage limit」でオフにできる。
  - **なぜ注目されているか**: この挙動は#18980・#35744・#36320・#47276など複数のIssueで長期間繰り返し要望されてきた機能。公式対応前は、tmuxでレート制限メッセージを監視しリセット時刻に自動で「continue」を送信する非公式ツール（`claude-auto-retry`、`autoclaude`等）がコミュニティで複数作られるほど需要が強かった。
  - **使いどころ**: `/loop`やWorkflowで長時間の自動化を回していて上限停止に気づかず放置してしまうことがあるなら、デフォルトONのままでよい。逆に「上限に達したら人が確認するまで止めたい」運用なら`/config`で明示的にオフにする。

- **[公式][実務][企画] Claude Code v2.1.234 — `/goal`がバックグラウンドタスクを30分以上待った場合に自動で様子を見に行くように** — https://github.com/anthropics/claude-code/releases/tag/v2.1.234
  - **何が起きたか**: 同v2.1.234で、複数ターンにまたがり完了条件を満たすまで自律的に作業を続ける`/goal`コマンドが、バックグラウンドタスクの完了を30分以上待ち続けている場合に自動でチェックインする挙動になった。
  - **なぜ注目されているか**: `/goal`は5/12のv2.1.139で「完了条件を設定して数ターン〜数日単位で自律的に動かす」ために追加された機能。一方で、バックグラウンド処理の完了通知が反映されずセッションが無反応のまま止まる不具合（issue #40462「Claude silently stalls mid-session」、#68992「バックグラウンドタスクが running のまま止まる」など）が繰り返し報告されてきた系統の問題への改善。
  - **使いどころ**: この`scheduled-agents`のようにroutineや`/loop`で長時間の自律作業を任せる運用では、`/goal`を使うとバックグラウンドタスクの完了に気づかず放置される事故を今回の更新で減らせる。「AIに丸投げして放置してみる」系のYouTube企画をやるなら、この挙動改善は前提として押さえておくとよい。

- **[公式][実務] Claude Code v2.1.234 — バックグラウンドサブエージェントの権限プロンプトで、セッション単位の許可回答が失われる不具合を修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.234
  - **何が起きたか**: 同v2.1.234で、バックグラウンドで動くサブエージェントがツール権限を求めるプロンプトに対し「このセッションの間は許可」のように回答しても、その回答が保持されずに失われる不具合が修正された。
  - **なぜ注目されているか**: バックグラウンドサブエージェントの権限プロンプトまわりは、権限が承認前に自動拒否されユーザーに表示すらされない（issue #36042「Background sub-agents silently blocked by permission prompts」）、許可リストに追加しても効かない（#34095）など、この1年繰り返しバグ報告が続いてきた系統の不具合。今回はそのうち「セッション単位の回答が保持されない」部分の修正。
  - **使いどころ**: Workflowやサブエージェント経由でCDK/ECSまわりの自動化を回している場合、権限プロンプトに答えたはずなのに同じ確認が何度も出ていたなら、この修正で減る可能性がある。経験の浅いメンバーに触らせる自動化ほど、権限まわりの挙動が安定することはレビュー品質の一貫性にも効いてくる。
