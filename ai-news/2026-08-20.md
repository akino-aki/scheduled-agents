- **[実務] Claude Code v2.1.236 — auto modeの「作業ツリーはクリーンか」判定が `status.showUntrackedFiles=no` で誤魔化せなくなる修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.236
  - **何が起きたか**: 8/19リリースのv2.1.236で、auto modeが破壊的なgitコマンドの実行可否を判断する際の「作業ツリーがクリーンか」チェックが、リポジトリの`status.showUntrackedFiles=no`設定によって誤魔化せないよう修正された。これまではこの設定さえあれば、実際には未追跡ファイルが残っていてもクリーンと判定されていた。
  - **なぜ注目されているか**: この「クリーンな作業ツリー確認」は、Claudeが`git clean -fd`を無断実行し未追跡ファイルを削除した事故（issue #45974）や、worktreeの自動クリーンアップが10日分の未コミット作業を消してしまった事故（issue #46444）を受けてv2.1.183で導入された安全網。今回はその判定ロジック自体が設定次第で無力化されうる抜け穴を塞いだ格好になる。
  - **使いどころ**: `.gitconfig`等で`status.showUntrackedFiles=no`を使っているリポジトリでauto modeを使っているなら、これまで安全網が効いていなかった可能性がある。経験の浅いメンバーがauto modeで作業する環境ほど、v2.1.236へのアップデートを優先する価値がある。

- **[実務] Claude Code v2.1.236 — `Monitor`ツールの許可ルールがauto mode中は退避され、Bashと同じ審査を通るように** — https://github.com/anthropics/claude-code/releases/tag/v2.1.236
  - **何が起きたか**: 同v2.1.236で、`Monitor`ツールに対する許可ルール（allow rule）がauto mode有効中は一時的に無効化され、Bashコマンドと同様にauto modeの安全性分類器（classifier）による審査を必ず通るようになった。
  - **なぜ注目されているか**: auto modeは、無制限のPython/Node実行のような過度に広い許可ルールがあると分類器の審査自体をすり抜けられてしまうため、そうした広すぎる許可ルールを意図的に退避させる設計になっている。今回`Monitor`もその対象に加わった＝これまでMonitor経由なら審査を素通りできる余地があったということになる。
  - **使いどころ**: `/loop`やWorkflowの`Monitor`ツールで長時間ポーリングする運用をしているなら、v2.1.236以降は監視対象のコマンドもBashと同様に都度審査される。無人運用中に想定外の確認待ちや停止が増えたら、この変更が原因の可能性がある。

- **[実務][企画] Claude Code v2.1.236 — `SendMessage`に`notify_when_idle`追加、他セッションのアイドル化を一度だけ通知** — https://github.com/anthropics/claude-code/releases/tag/v2.1.236
  - **何が起きたか**: 同v2.1.236で、`SendMessage`に`notify_when_idle`オプションが追加され、あるClaude Codeセッションが別セッションに対し「次にアイドル状態になったら一度だけ知らせてほしい」と依頼できるようになった。オプトイン・ポーリングなしの一回限りの通知で、macOS/Linuxが対象。
  - **なぜ注目されているか**: セッション間メッセージングは8/7のv2.1.224で追加されて以来、8/8で双方向化、8/13で`@`メンションが加わるなど段階的に拡張されてきた機能（8/8・8/9・8/15付ダイジェストで既報）。今回はその延長線上に「相手の完了を待つ」という具体的なユースケースが公式に組み込まれた。
  - **使いどころ**: 複数worktreeやサブエージェントセッションを並行で走らせ、片方の完了を待ってから次の指示を出す設計をしているなら、ポーリングなしで完了検知ができる。「AI同士が声を掛け合いながら作業する」YouTube企画のネタとしても引き続き温めておける。

- **[実務] Claude Code v2.1.236 — macOSサンドボックスのワイルドカード読み取り拒否がリネームで回避できなくなる修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.236
  - **何が起きたか**: 同v2.1.236で、macOSサンドボックスのワイルドカード読み取り拒否ルール（例: `**/.env`）が、許可された読み取り領域の内側でも優先されるようになり、該当ディレクトリ配下も対象に含まれ、拒否対象ファイルをリネームしても回避できなくなった。
  - **なぜ注目されているか**: リリースノート自身が「リネームによる回避ができなくなった」と明記しており、これまで`.env`のような機密ファイルを拒否ルールで守っていても、ファイル名を変えるだけで読み取りをすり抜けられる余地があったことを示している。
  - **使いどころ**: マルチアカウント環境でAWSクレデンシャルや`.env`をサンドボックスの読み取り拒否ルールで守っている構成なら、v2.1.236でその防御が強化される。macOS上でClaude Codeを動かしているなら特にアップデートを確認しておきたい。
