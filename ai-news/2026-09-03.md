  - **使いどころ**: 個人開発のクイズアプリでAI採点の精度がOpus 5高effortでも頭打ちなら、`/model fable`で一度evalしてみる価値がある。CDK/ECSの日常レビューには速度・価格面で過剰なので今すぐは不要。

- **[公式][実務] Claude Code v2.1.257 — auto modeに`permissions.blockReadsOutsideWorkingDirectories`追加、working directory外への初回ファイル読み取りで確認プロンプト** — https://github.com/anthropics/claude-code/releases/tag/v2.1.257
  - **何が起きたか**: 同v2.1.257で、auto mode中に最初にworking directory外のファイルを読もうとした際、確認プロンプトを出しそこでブロックを選べる設定`permissions.blockReadsOutsideWorkingDirectories`が追加された。
  - **なぜ注目されているか**: 8/27・9/2既報のauto mode安全性ルール群（classifierタブ、クラウドメタデータ資格情報取得を止めるContainment Escapeルール）の延長線上にある。これまでauto modeの制御は書き込み・実行の危険操作が中心で、working directory外の読み取り自体には確認が挟まっていなかった。
  - **使いどころ**: マルチアカウントのAWS環境でauto modeを使うなら、この設定を有効にしておくと`~/.aws/credentials`など作業ディレクトリ外の機密ファイルへ意図せずアクセスする前に一呼吸置ける。経験の浅いメンバーの環境ほど既定でオンにしておく価値がある。

- **[公式][実務] Claude Code v2.1.258 — リモート/スケジュールされたセッションで、権限承認の再送信に失敗すると会話が壊れる不具合を修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.258
  - **何が起きたか**: 9/1リリースのv2.1.258で、リモート/スケジュールされたセッションにおいて権限承認の再送信が適用できなかった場合に「user messages must have non-empty content」エラーで以降の会話が続けられなくなる不具合が修正された。
  - **なぜ注目されているか**: このダイジェスト自体もスケジュール実行の一つで、人が見ていない無人実行中に権限確認が絡む処理があると会話ごと止まりうるという、自動化ならではの障害パターン。9/1既報の「Always allowが新規プロジェクトで保存されない」不具合修正に続き、無人実行時の権限まわりの信頼性改善が続いている。
  - **使いどころ**: routineや自作の`/loop`でBash許可など確認が絡む処理を無人実行させているなら、バージョンを上げておくと不意に会話が固まって止まる事故が一つ減る。自作routineの安定性チェック項目として押さえておくとよい。
