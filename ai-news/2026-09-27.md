- **[実務][企画] issue #94740 — auto modeでPreToolUse hookの`"allow"`判定が`permissions.allow`ルールと違い、classifierの再審査をスキップできない仕様に対する改善要望（9/16報告, 未対応）** — https://github.com/anthropics/claude-code/issues/94740
  - **何が起きたか**: auto modeの判定順は「①allow/ask/denyルールに一致→即決」「②読み取り・作業ディレクトリ内編集は自動承認」「③それ以外はclassifierへ」となっているが、PreToolUse hookが返す`"allow"`は①では扱われず、③のclassifierに送られてブロックされうる（"deny"/"ask"はhook側の判定がそのまま尊重される）。報告者は自作のBashコマンド検証エンジン（引数の形まで見る、単純なprefixルールでは表現できないポリシー）が使えず、7/22〜9/16の直近2期間で計160件のブロックのうち自作ポリシーなら許可していたはずの3件がclassifierに止められたという実測データを添えている。
  - **なぜ注目されているか**: 「hookで"allow"と判定した処理は信頼してよい」という直感に反し、実装は"deny"/"ask"だけ尊重して"allow"だけclassifierに再送される非対称な仕様になっている。回避策は同じ判定ロジックを`permissions.allow`のprefixルールとして重複管理するしかなく、hookとルールがずれていく保守負担が生じる。
  - **使いどころ**: skill/hook/routineを自作してauto modeで無人実行させているなら、PreToolUse hookの"allow"を「classifierを完全にスキップする」設計だと思い込まない方がよい。厳密に自動実行させたいコマンドは、現状`permissions.allow`のルール側にも同じ条件を明示しておく二重管理が必要。

- **[公式][企画] Claude Code v2.1.283（9/25）— routine（スケジュール実行）の既定時刻が「ちょうど正時（9:00等）」を避け数分ずらした時刻になるよう変更、公式ドキュメントも「正時指定は数分遅れうる」と明記** — https://code.claude.com/docs/en/routines#add-a-schedule-trigger
  - **何が起きたか**: v2.1.283のリリースノートに「Changed new routine schedules to default to a few minutes past the hour, with a note that routines set exactly on the hour can start several minutes late」と明記された。公式ドキュメント（Routines）にも「9:00のようにちょうど正時で予約すると数分遅れて開始することがある。予定時刻に近づけたいなら9:07のように数分ずらすとよい」という記述が追加されている。
  - **なぜ注目されているか**: 大量のユーザーのroutineが正時（0分・30分）に一斉に発火することで生じる負荷集中が遅延の原因と読み取れる内容で、この仕組みは今回のダイジェスト自身が依存しているスケジュール実行機能そのものに関わる。
  - **使いどころ**: 自作routineを正時（毎時0分・9:00など）で組んでいるなら、数分ずらした時刻（9:07等）に変更しておくと開始遅延を避けやすい。このダイジェストのroutineも実行時刻を確認し、正時指定になっていれば見直す価値がある。

- **[実務][企画] issue #95450 — cloud routineが「エラーも出さず無言で何もしない」「PENDINGのまま数時間〜3日stall」「同一トリガーが無関係に二重発火」する信頼性問題（9/18報告, 未修正）** — https://github.com/anthropics/claude-code/issues/95450
