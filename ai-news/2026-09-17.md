- **[実務] Claude Code v2.1.273（9/15）— REVIEW.mdに@メンションや複数行コードスパンがあると審査ルール全体が無視される不具合を修正、除外対象を該当行だけに限定** — https://code.claude.com/docs/en/code-review
  - **何が起きたか**: v2.1.273のリリースノートに「Fixed a whole REVIEW.md being ignored because of an @-mention, a code span wrapped across lines, or a backticked HTML tag; only lines linking to changed files are withheld」と明記されている。これまではREVIEW.md内に@メンション・複数行にまたがるコードスパン・バッククォートで囲んだHTMLタグが含まれていると、ファイル全体が審査に反映されなくなっていたが、影響を受ける行だけが除外されるよう修正された。
  - **なぜ注目されているか**: REVIEW.md はTeam/Enterprise向けのGitHub連携Code Review機能（PRへの自動レビュー）専用の設定ファイルで、「🔴Importantの基準をこのリポジトリではどう定義するか」「生成コードやlockfileはレビュー対象から外す」「新規APIルートには必ず統合テストを要求する」といったチーム固有のレビュー基準をここに書く。この不具合があると、README風の見出しやコード例、担当者への@メンションなど普通に書きそうな内容を含めただけでファイル全体が無視され、しかもエラーは出ないため誰も気づかないままチームのレビュー基準がまったく効いていない、という状態になり得た。
  - **使いどころ**: 経験の浅いメンバーのレビュー品質を揃える目的でTeam/EnterpriseのCode Review機能＋REVIEW.mdを使っている（または導入を検討している）なら、v2.1.273以降であることを確認し、REVIEW.mdの内容が実際に反映されているか一度PRで確認するとよい。なお、ローカルの`/code-review`コマンドはそもそもREVIEW.mdを読まない仕様なので対象外。

- **[企画][実務] GitHub issue #94872（9/16報告、未修正）— バックグラウンドサブエージェントの起動記録に状態・時刻が一切残らず、セッション終了後も「実行中」表示が消えない** — https://github.com/anthropics/claude-code/issues/94872
  - **何が起きたか**: サブエージェント起動時に書き込まれる`~/.claude/projects/<project>/<session-id>/subagents/agent-<id>.meta.json`にはagentTypeやdescriptionはあるがstatus・開始時刻・終了時刻が一切記録されておらず、親プロセスが完了マーカーを書かずに終了する（セッション終了やマシン再起動など）と、そのサブエージェントは「実行中」のまま永久に表示され続けると報告されている。報告者の環境では757件の“実行中”表示のうち750件が直近の起動より前の日付、最古のものは832時間（約35日）前だった。
  - **なぜ注目されているか**: 完了記録が無いことからしか生存確認ができない設計そのものが原因で、親プロセスが正常終了しない限り検知不能という構造的な欠陥。このダイジェスト自体もスケジュールされたルーチンからサブエージェントやWebFetchを多数呼び出しており、他人事ではない種類の問題。
  - **使いどころ**: 自作`/loop`やWorkflow、スケジュールroutineでバックグラウンドサブエージェントを多用しているなら、`claude agents`などの「実行中」表示を鵜呑みにせず、長時間セッションを保持するマシンでは定期的にメタデータの掃除が必要になる可能性がある。現時点では未修正なので、様子見が無難。

- **[企画][実務] Claude Code v2.1.271（9/14）— Workflowがusage limit到達時にエージェントを打ち切らず一時停止・自動再開するよう変更、7月報告の「limit到達でblank contextから再実行され作業が無駄になる」問題に対応** — https://github.com/anthropics/claude-code/issues/80253
  - **何が起きたか**: v2.1.271のリリースノートに「Improved dynamic workflows to pause when you hit your usage limit and continue automatically when it resets, instead of dropping the affected agents」とある。7/22報告のissue #80253は、multi-agent Workflow実行中にsession limitに達すると、実行中だったサブエージェントがコンテキストを失った状態から自動リトライされ、既に完了していた作業（visual QA等）を最初からやり直すことでusageの約23〜27%が無駄になったと報告していた（この issue 自体は「対応しない」でクローズ済み）。今回の変更は、この種の「limit到達でエージェントの作業を失う」問題に、一時停止＋自動再開という形で応えたものと言える。
  - **なぜ注目されているか**: ただし全て解決したわけではない。9/12報告のissue #93874（未修正）では、session limit到達後もWorkflowが新規エージェントを189件連続で起動し続け、いずれもモデル応答ゼロのまま失敗した事例が報告されており、「limit到達後にエージェントを無駄に起動し続ける」側の問題はまだ残っている。
  - **使いどころ**: 自作`/loop`やWorkflowで無人実行するルーチンを組んでいるなら、usage limitに達しても実行中エージェントの作業が失われにくくなった点は素直に恩恵がある。ただしlimit到達後の新規エージェント起動が止まらないケースはまだ報告されているため、コスト監視（`claude.ai/analytics`等）は引き続き必要。
