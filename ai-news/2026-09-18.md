- **[公式][実務] Claude Code v2.1.274 — `/code-review`がサブエージェント大量起動方式から「専用チューニングの無いモデルでは軽量インラインプロンプト」方式に変更、同時に「セルフレビュー化」の懸念も表面化** — https://github.com/anthropics/claude-code/releases/tag/v2.1.274
  - **何が起きたか**: v2.1.274で「`/code-review`は専用チューニングを持たないモデルでは、多数のレビューsubagentを起動する代わりに軽量なインラインレビュープロンプトを使う」に変更された。同日報告のissue #95165では、desktop版`/code-review`が以前からインライン実行（文脈分離なし）で、AI自身が「自分のPRをレビューしている」と明言した例も報告されている。
  - **なぜ注目されているか**: 8/21の変更でsubagent方式（finder+verifier、最大14エージェント）が入って以降、8/24報告のissue #89249は通常規模のPR（+834/-55行）で約6,600万トークン・23分・週次プラン上限の約20%を消費する「10倍コスト増」を指摘していた。今回のインライン化はこのコスト問題への対応と見られる一方、インライン実行は執筆したのと同じ文脈でレビューするためセルフレビューになりやすいという副作用がissue #95165で指摘されている。
  - **使いどころ**: プルリクレビューの品質を揃える取り組みで`/code-review`を使っているなら、コストは下がった可能性が高いが「独立した第三者視点のレビュー」では無くなった点に注意。重要なPRではこのインラインチェックだけに頼らず、人間によるレビューを引き続き必須にするとよい。

- **[公式][企画] Claude Code v2.1.274 — hookで駆動される長時間セッション（`/goal`など）が再圧縮できず「Prompt is too long」のまま死ぬ不具合を修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.274
  - **何が起きたか**: v2.1.274で、hookで駆動されるセッション（`/goal`など）が、一度コンテキストを圧縮した後に再び溢れた場合、圧縮されず「Prompt is too long」のまま止まっていた不具合が修正された。あわせて、圧縮を経たセッションを`--continue`/`--resume`で再開すると有効だった`/goal`が失われる不具合も修正された。
  - **なぜ注目されているか**: 5月報告のissue #58192は、`/goal`の完了条件テキストがStop hookの評価プロンプトに毎回まるごと埋め込まれる設計のため、条件が長いとhookの評価自体がコンテキスト上限を超え、以後すべてのStopが失敗し続けるという構造的な問題を指摘していた。回避策は`/goal clear`しかなかった。
  - **使いどころ**: 自作hookやroutineで`/goal`を使い、長めの完了条件や長時間セッションを回しているなら、これまで途中で無言のまま止まっていた原因の一つが解消された。バージョンを上げるだけで効くので、既存の`/goal`運用があるなら更新しておく価値がある。

- **[公式][企画] Claude Code v2.1.274 — 環境変数`CLAUDE_CODE_MCP_STARTUP_WAIT_MS`追加、ヘッドレス/SDKの初回ターンでMCPサーバーの接続待ち時間を調整可能に** — https://github.com/anthropics/claude-code/releases/tag/v2.1.274
  - **何が起きたか**: v2.1.274で環境変数`CLAUDE_CODE_MCP_STARTUP_WAIT_MS`が追加され、ヘッドレス/SDKの最初の非対話ターンがMCPサーバーの接続完了をどれだけ待つかを指定できるようになった（0指定で待たない）。
  - **なぜ注目されているか**: CLI 2.1.144以降、初回のAPIリクエストはstdio MCPサーバーの接続完了を待たなくなっており、実質的な待機時間は約2秒しかなかった。issue #76239は、MCPサーバーの起動がこれより遅い場合ツールが使えないまま初回ターンが進んでしまう回帰（特に1回のクエリで完結するヘッドレス利用で顕著）を指摘していた。
  - **使いどころ**: Agent SDK経由でクイズアプリの出題登録〜公開自動化を組む、あるいはこのダイジェストのようなヘッドレスのスケジュールroutineでMCPサーバーを使うなら、起動直後にツールが認識されない事故を減らせる。MCP接続が遅い構成では、この変数を伸ばして使うとよい。
