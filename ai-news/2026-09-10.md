- **[公式][実務] Claude Code v2.1.266（9/8）— 前日v2.1.265で入った`CLAUDE_CODE_USE_GATEWAY`のリグレッションを即日修正、LLMゲートウェイ/プロキシ構成での全リクエスト失敗を解消** — https://github.com/anthropics/claude-code/releases/tag/v2.1.266
  - **何が起きたか**: 非公開（undocumented）の環境変数`CLAUDE_CODE_USE_GATEWAY`は、これまで単独指定時は無視される仕様だったが、9/8リリースのv2.1.265でこの変数を設定しているだけでCloud gatewayへのサインインを強制するよう変わってしまい、APIキーや`apiKeyHelper`、カスタム認証ヘッダーと併用する構成では全リクエストが「Not signed in to the Cloud gateway」で失敗するようになっていた。同日中にv2.1.266でこの挙動が撤回され、単独指定時は再び無視される元の仕様に戻った。設定変更は不要。
  - **なぜ注目されているか**: 自前のLLMゲートウェイやプロキシを挟んでClaude Codeを使う企業向け構成に影響する変更が、リリースの翌日ではなくその日のうちに気づかれ撤回されるという珍しい即日ロールバック事例。ドキュメント化されていない環境変数の挙動変更が既存構成に静かに影響する、という点でも実例として押さえておく価値がある。
  - **使いどころ**: 個人開発やCDK/ECSの日常レビューでは直接関係しない変数だが、社内でLLMゲートウェイ経由のプロキシ導入を検討しているなら、「未指定の環境変数でも挙動が変わることがある」実例として頭の片隅に置いておくとよい。今すぐの対応は不要。

- **[実務][企画] GitHub issue #92833（9/8報告、未修正）— Cowork スケジュールタスクが9/2のDesktopアップデート以降、サンドボックスVM内ツールを権限ルールで100%拒否** — https://github.com/anthropics/claude-code/issues/92833
  - **何が起きたか**: 9/2のClaude Desktopアップデート（同梱Claude Code 2.1.258）以降、Cowork機能のスケジュールタスクで`mcp__workspace__bash`や`mcp__workspace__web_fetch`（サンドボックスVM内ツール）が権限ルールにより毎回拒否されるようになったと報告されている。9/2 10:36 UTCまでは227回連続成功していたのが、それ以降は`echo ok`のような単純なコマンドすら拒否され、`bypassPermissions`（Skip all approvals）や`auto`モードでも回避できない。9/9時点で修正は入っていない。
  - **なぜ注目されているか**: 拒否はユーザーが上書きできない"rule"判定で発生し、セッション開始時の`init`イベントにはツールがまだ一覧表示されている（＝呼び出し時にサイレントにブロックされている）ことまで報告者が確認済み。無人実行中に誰も気づかないまま全タスクが失敗し続けるという、スケジュール実行の自動化routine全般が警戒すべき種類の障害。
  - **使いどころ**: Claude Desktop の Cowork スケジュールタスクでWindows環境の自動化を組んでいる、または組む予定があるなら、直近1週間の実行ログを確認し意図せず全滑りしていないか点検した方がよい。このダイジェスト自体はCLIのheadlessなroutineで別経路のため直接の影響はないが、Coworkベースの自動化に手を広げる際は要注意。修正が入るまでは様子見が無難。
