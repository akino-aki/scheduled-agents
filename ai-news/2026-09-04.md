- **[公式][実務][企画] Claude Code v2.1.259 — 複数セッション同時起動時に`~/.claude.json`を互いに上書きし合い、workspace trustやMCP設定が消える不具合を修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.259
  - **何が起きたか**: 9/2リリースのv2.1.259で、複数のClaude Codeセッションを同時に動かすと`~/.claude.json`への書き込みが競合し、workspace trustの再設定やMCP・プロジェクト設定の消失が起きる不具合が修正された。
  - **なぜ注目されているか**: 2月26日報告のissue #28829は「11個以上のセッションを同時起動するとJSON破損（Unexpected EOF）でクラッシュする」重大リグレッションとして報告しており、同日だけで類似issueが3件重複報告されるほど影響が広範だった。原因はファイルロックの無い非アトミックな読み書き競合で、`toolUsage`など頻繁に更新されるランタイム状態と設定が同じファイルに同居していたことが背景にある。
  - **使いどころ**: `/loop`やWorkflow、複数worktreeのセッションを同時に多数立ち上げる使い方をしているなら、これまで気づかずworkspace trustやMCP設定が消えていた事故が解消される。CDK/ECSの調査を複数セッション並行で回す運用をしているなら、バージョンを上げておく価値が大きい。

- **[公式][実務][企画] Claude Code v2.1.259 — `--permission-prompts none`追加、無人のヘッドレスホストで権限確認が発生する操作を自動拒否に** — https://github.com/anthropics/claude-code/releases/tag/v2.1.259
  - **何が起きたか**: 同v2.1.259で`--permission-prompts none`が追加され、指定すると本来なら確認プロンプトが出るはずの操作が自動的に拒否される。auto modeなど現在の権限モード自体の判断ロジックはそのまま動き続ける。
  - **なぜ注目されているか**: issue #77817は「v2.1.206で無人のスケジュールタスクが`permissions.defaultMode`を引き継がなくなり、11個の本番routineが軒並みManualモードへ静かに戻され、10分おきに実行するタスクが1時間に30回以上権限確認で止まった」と報告していた。無人実行で確認プロンプトに誰も答えられず処理が止まってしまう、というこのダイジェスト自体が抱えうるリスクへの対応が今回のフラグになる。
  - **使いどころ**: このダイジェストのような無人のroutineや自作`/loop`で、想定外の操作が権限確認で無限に止まってしまうリスクを減らせる。ただし「確認が要る操作は許可ではなく拒否になる」フラグなので、必要な操作は事前に許可ルールへ足しておく前提で使うとよい。

- **[公式][実務][企画] Claude Code v2.1.259 — 組織向け`managedMcpServers`設定を追加、HTTP/SSEのMCPサーバーを全ユーザーへ一括配布可能に** — https://github.com/anthropics/claude-code/releases/tag/v2.1.259
  - **何が起きたか**: 同v2.1.259で、組織の管理設定に`managedMcpServers`が追加された。`.mcp.json`と同じ形式のエントリをHTTP/SSEサーバーに限り組織全体へ一括配布できる（コマンド実行型のエントリは配布対象外）。既存の`allowedMcpServers`/`deniedMcpServers`はこの配布後のサーバーに対しても許可・拒否フィルタとして働く。
  - **なぜ注目されているか**: これまでMCPサーバーの共有はプロジェクトの`.mcp.json`をgit経由で配る方式が中心で、各自が信頼ダイアログを個別に通す必要があった。`managedMcpServers`は管理設定側から配布するため、信頼ダイアログを都度通さずに組織内で同じMCPサーバー構成を強制できる点が異なる。
  - **使いどころ**: 経験の浅いメンバーのレビュー品質を揃えたいなら、CDK/ECS向けの社内MCPサーバー（例えば社内AWSナレッジベースやIaCチェック用）を用意し`managedMcpServers`で全員に配れば、各自の`.mcp.json`設定のばらつきに依存せず同じツールをレビュー環境に強制できる。個人開発では使う場面がないので今すぐは不要。

- **[公式][実務] Claude Code v2.1.259 — Bashの`Read()` deny ruleが、オプション引数値や`git diff`/`git grep`のファイル指定、`cd DIR && cat FILE`のようなコマンド連結をすり抜けていた不具合を修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.259
  - **何が起きたか**: 同v2.1.259で、`--ignore-revs-file=.env`や`-f.env`、`@file`のようなオプション引数値、`git diff`/`git grep`のファイル操作対象、`cd DIR && cat FILE`のようなコマンド連結が`Read()` deny ruleをすり抜けていた不具合が修正された。`grep -r`/`cp -r`が拒否対象ファイルを含むディレクトリに対して実行された場合も、以後は確認プロンプトが出る。
  - **なぜ注目されているか**: 9/2付ダイジェストで既報の「リダイレクトや`tac`・`egrep`などの別名コマンドがdeny ruleをすり抜ける」不具合と同じ系統で、今回はその第2弾にあたる。Bash deny ruleの抜け穴が今月に入って複数回に分けて塞がれ続けている状況で、まだ他の抜け道が残っている可能性を示唆している。
  - **使いどころ**: `.claude/settings.json`に`.env`などをdenyルールで守っているなら、これまで`git diff .env`のような経路ですり抜けていた可能性がある。経験の浅いメンバー向けのBash許可・拒否ルールのレビューチェックリストに「オプション引数値やコマンド連結もすり抜けないか」を追加しておくとよい。
