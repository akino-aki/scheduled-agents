- **[公式][実務] Claude Code v2.1.238 — 対話セッションの無制限メモリ増加を修正（サブエージェントのツール結果を表示ウィンドウ外で解放）** — https://github.com/anthropics/claude-code/releases/tag/v2.1.238
  - **何が起きたか**: 8/20リリースのv2.1.238で、長時間の対話セッションにおけるメモリの無制限な増加が修正された。サブエージェントのツール実行結果が、直近の表示ウィンドウから外れた時点でメモリから解放されるようになった。
  - **なぜ注目されているか**: 長時間セッションでメモリが増え続ける不具合は3月報告のissue #37240（2〜3時間の使用で約500MB/時間のペースで増加し、16GBマシンで4GBに到達）以降繰り返し報告されてきた系統。原因は会話履歴やツール結果がガベージコレクトされない点と推測されており、今回はそのうちサブエージェントのツール結果の保持部分に対処した。
  - **使いどころ**: CDK/ECSの大規模リポジトリ調査などでサブエージェントを多用しながら1セッションを長時間使い続けるなら、以前より安定して動く可能性がある。worktreeで複数サブエージェントを長時間並列させるYouTube企画的な使い方をするなら、効果を体感しやすい。

- **[公式][実務][企画] Claude Code v2.1.238 — セッション間メッセージングで「送ったのに届いていない」サイレント失敗を解消** — https://github.com/anthropics/claude-code/releases/tag/v2.1.238
  - **何が起きたか**: 同v2.1.238で、他セッションへの`SendMessage`が、相手が受信拒否設定（`crossSessionInbound: "refuse"`）の場合に送信側へ「refused」と明示的に返すようになった。相手の受信キューがレート制限や満杯でメッセージを取りこぼす場合も、送信側に通知されるようになった。従来はどちらも送信側からは成功したように見えていた。
  - **なぜ注目されているか**: セッション間メッセージングは8/7のv2.1.224で追加されて以来、8/8で双方向化、8/13で`@`メンション追加、8/19で`notify_when_idle`追加と段階的に拡張されてきた機能（8/8・8/9・8/15・8/20付ダイジェストで既報）。機能が広がるたびに「実は届いていない」というサイレントな失敗パターンが残っていたが、今回はその2つの穴を塞いだ形。
  - **使いどころ**: 複数worktreeでセッションを並行実行し、`@`メンションや`notify_when_idle`で互いに連携させる設計をしているなら、メッセージ未達に気づかず待ち続ける事故を避けやすくなる。「AI同士が声を掛け合いながら開発する」YouTube企画を検討しているなら、この信頼性向上は地味に効いてくる。

- **[公式][実務] Claude Code v2.1.237 — 前置き・実況を省く「Concise」出力スタイルを追加** — https://github.com/anthropics/claude-code/releases/tag/v2.1.237
  - **何が起きたか**: 8/20リリースのv2.1.237で、結果を先に示し前置きや実況的な説明を省略する組み込みの出力スタイル「Concise」が追加された。作業の徹底度は変えないまま、`/config`のOutput styleから選択できる。
  - **なぜ注目されているか**: これまで組み込みの出力スタイルは通常の会話調が基本で、簡潔な出力にしたい場合はCLAUDE.mdやプロンプト側で個別に指示する必要があった。今回「結果ファースト・説明を減らす」というニーズに応える選択肢が標準機能として用意された。
  - **使いどころ**: PRレビューの下調べや調査結果を素早く確認したいだけの場面で`Concise`に切り替えると、出力を読む時間そのものを削れる。経験の浅いメンバーに触らせる自動化スクリプトの出力を短く保ちたい場合にも使える。

- **[公式][実務] Claude Code v2.1.238 — project設定由来の`headersHelper`は認証情報の環境変数を継承せずに実行、trust承認も必須に** — https://github.com/anthropics/claude-code/releases/tag/v2.1.238
  - **何が起きたか**: 同v2.1.238で、MCPサーバーの動的認証ヘッダーを生成する既存の`headersHelper`機構について、project由来の`.mcp.json`・プラグイン・agentファイルで指定されたものは、そのフォルダのtrustダイアログ承認が前提になり（`claude -p`でも同様）、かつ認証情報系の環境変数を継承せずに実行されるよう変更された（ユーザー設定・管理設定・claude.aiスコープのヘルパーはClaude設定ディレクトリから実行）。あわせて、プラグインマーケットプレイス向けにも新規`headersHelper`（トークン発行コマンドを実行する仕組み）が追加された。
  - **なぜ注目されているか**: リポジトリに同梱されるproject設定を無条件に信用しない、という方針は8/15付ダイジェストの`sandbox.ripgrep`項目や8/19付ダイジェストのMCPシークレット露出修正と同じ系統。今回の変更は、project設定由来のヘルパーコマンドがこれまで認証情報の環境変数を引き継いだ状態で実行されていたことを示しており、その経路を塞いだ形になる。
  - **使いどころ**: マルチアカウント環境でAWS系の認証情報を環境変数で扱っている場合、外部から取り込んだリポジトリのproject設定に`headersHelper`が仕込まれていても認証情報が漏れる経路にはならなくなる。経験の浅いメンバーが外部プラグイン・MCPサーバーを追加する運用をしているなら、この設計を前提にレビュー観点を減らせる。
