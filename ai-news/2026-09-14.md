- **[公式][実務] Claude Code v2.1.268（9/10）— self-hosted runnerに`--remove-session-state`追加、セッション終了後も`_sessions/`配下に残り続けていた作業ディレクトリを自動削除可能に** — https://github.com/anthropics/claude-code/releases/tag/v2.1.268
  - **何が起きたか**: v2.1.268で`claude self-hosted-runner --remove-session-state`（デフォルトOFF）が追加された。有効にすると、セッション終了時に`<base-dir>/_sessions/`配下のそのセッション専用ディレクトリが削除される。
  - **なぜ注目されているか**: self-hosted runnerは、Claude Codeのクラウドセッションを自社ネットワーク内（社内VPC等）のホストで実行し、外部公開していない内部サービスやDBに直接アクセスさせられるTeam/Enterprise向けのベータ機能。これまでは削除オプションが無く、セッションディレクトリが`_sessions/`配下に残り続ける仕様だったため、多数のセッションをこなすランナーではディスクを圧迫しうる状態だった。
  - **使いどころ**: マルチアカウントAWS環境でAuroraなど内部DBに直接繋がるrunnerホストを自社EC2/ECSで運用する構想があるなら、採用時にこのフラグを有効化しておくとディスク管理の手間が減る。個人開発では対象外なので今すぐの対応は不要。

- **[公式][企画] Claude Managed Agents（9/10）— permission policyに`auto`追加、bashなどのツール呼び出しをAPIサーバー側でリスク評価し許可・拒否・確認待ちを自動判定** — https://platform.claude.com/docs/en/managed-agents/permission-policies
  - **何が起きたか**: API経由でカスタムエージェントを構築・実行する「Claude Managed Agents」に、permission policyの新種別`auto`が追加された。従来の`always_allow`（無条件実行）と`always_ask`（毎回確認待ち）の2択に加え、`auto`ではサーバーが呼び出し内容とそれまでの会話内容を見て、実行・拒否・確認待ちの3通りを呼び出しごとに自動判定する。
  - **なぜ注目されているか**: これまでは「全部自動実行」か「毎回人間の承認待ち」の二択しかなく、無人自動化を組もうとすると危険な操作まで自動実行してしまうか、逆に何もかも確認待ちで自動化の意味が薄れるかのトレードオフを迫られていた。`auto`は危険と判定した呼び出しだけを拒否・確認待ちに回すことで、その中間を埋める。
  - **使いどころ**: Claude Code CLIではなくAPI経由でエージェントを組む別製品（Managed Agents）の機能だが、「無人実行するタスクにどこまで権限を渡すか」という設計判断は、このダイジェスト自体のroutineや個人開発のクイズアプリ自動化にも共通する論点。今すぐ使う場面はないが、将来Agent SDK/Managed Agentsで自動化を組む際の選択肢として覚えておく価値がある。
