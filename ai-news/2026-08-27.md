- **[公式][実務] Claude Code v2.1.246 — `/permissions`に「Auto mode」タブ追加、classifierの許可・拒否ルールを表示・編集可能に** — https://github.com/anthropics/claude-code/releases/tag/v2.1.246
  - **何が起きたか**: 8/25リリースのv2.1.246で、`/permissions`に新しい「Auto mode」タブが追加され、auto modeの安全性分類器（classifier）が使うルールをその場で表示・編集できるようになった。
  - **なぜ注目されているか**: このclassifierは6月下旬から大規模な信頼性問題が報告されていた領域で、issue #74351では6/20頃から`claude-opus-4-8 is temporarily unavailable`エラーが868件、classifierによる明示的な拒否が255件記録され、Anthropicが「解決済み」とした期間中も数百件の失敗が続いていたと報告されている。別のissue #62300では「直前のWriteツール呼び出しで見えている内容なのに、classifierがそれを認識せずBashを拒否する」という判断の不透明さも指摘されており、こうした信頼性・透明性への不満がユーザーをBypass permissions（全権限有効化）へ逃がす一因になっていた。今回のタブ追加は、その不透明だった判断ルールにユーザー側から手を入れられるようにした形。
  - **使いどころ**: auto modeを経験の浅いメンバーにも使わせる前提なら、展開前にこのタブでclassifierルールを一度確認し、想定通りの範囲だけが自動許可されているか点検する価値がある。「ブラックボックスだったauto modeの中身を覗く」というテーマはYouTube企画のネタにもなる。

- **[公式][実務] Claude Code v2.1.246 — Bash許可ルールでワイルドカードがサブコマンドより前にあると起動時に警告** — https://github.com/anthropics/claude-code/releases/tag/v2.1.246
  - **何が起きたか**: 同v2.1.246で、`Bash(git * main)`のようにワイルドカード`*`がサブコマンドより前の位置に置かれた許可ルールに対して、起動時に警告が表示されるようになった。
  - **なぜ注目されているか**: このパターンは`git branch main`のような想定外のサブコマンドや、`git -C /tmp main`のようにサブコマンドの前にオプションを挟んだコマンドにも一致してしまうため、書いた本人の意図より広い範囲を許可してしまいがちな典型的な書き方だった。今回はその危険な書き方自体を起動時に検知して知らせる形になった。
  - **使いどころ**: 経験の浅いメンバーがPRやsettings.jsonにBash許可ルールを追加する場面のレビュー観点が一つ増える。「ワイルドカードはサブコマンドより後ろに置く」をチェックリスト項目として明文化できる。

- **[公式][実務] Claude Code v2.1.243 — `modelPicker`設定を追加、複数のカスタムモデルをラベル付き・任意の順序で`/model`ピッカーに列挙可能に** — https://github.com/anthropics/claude-code/releases/tag/v2.1.243
  - **何が起きたか**: v2.1.243で`modelPicker`設定が追加され、Bedrock/Vertexなど任意のIDのモデルを、順序とラベルを指定して`/model`ピッカーに複数列挙できるようになった（組み込みの一覧に追加、または丸ごと置き換え）。
  - **なぜ注目されているか**: 従来`ANTHROPIC_CUSTOM_MODEL_OPTION`はカスタムモデルを1件しか登録できず、LiteLLMなどのゲートウェイ経由で複数の非Anthropicモデルにルーティングする構成では2件目以降をピッカーに出す手段がなかった（issue #58583）。ピッカーの表示ラベルを管理者設定側で制御したいという要望（issue #65476）も以前から出ており、今回はそうした複数の積み残し要望に応えた形。
  - **使いどころ**: 社内プロキシ/ゲートウェイ経由でBedrockの複数モデルを使い分けているなら、`modelPicker`でチームが選べるモデルをラベル付きで整理できる。経験の浅いメンバーに意図しないモデルを選ばせたくない場合の選択肢の絞り込みにも使える。

- **[公式][実務] Claude Code v2.1.243 — `modelPricing`設定を追加、組織の契約単価を`/cost`表示に反映可能に** — https://github.com/anthropics/claude-code/releases/tag/v2.1.243
  - **何が起きたか**: 同v2.1.243で管理者向けの`modelPricing`設定が追加され、組織が契約しているモデルごとの単価・割引率を`/cost`やステータスライン、テレメトリのコスト表示に反映できるようになった。これまではリスト価格（定価）がそのまま使われていた。
  - **なぜ注目されているか**: 割引契約があってもツール上のコスト表示は定価ベースのままだったため、実際の請求額とツールが示す金額がズレる状態が続いていた。今回はその差分を設定側で埋められるようにした。
  - **使いどころ**: 個人開発・小規模利用で定価のまま使っているなら今すぐは不要。Bedrock/Vertex経由で企業契約の割引が適用されている環境になったら、`modelPricing`を設定してコスト表示を実態に合わせておくと、AWS側のコスト管理と突き合わせて説明しやすくなる。
