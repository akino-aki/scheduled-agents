# 2026-08-09

- **[公式][実務] Claude Code、8/14からAuto modeがPro/Max/Teamの新規セッションで既定に** — https://code.claude.com/docs/en/auto-mode-config
  - **何が起きたか**: 2026年8月14日から、Pro/Max/Teamプランの新規セッションで権限モードの既定値が「Auto mode」（分類器が不可逆・破壊的・環境外向けの操作だけ止め、それ以外は無許可で実行）に変わる。自分で`defaultMode`を設定済みなら初回の切替プロンプトを承諾しない限り現状維持され、組織管理の既定値がある場合はそちらが優先される。
  - **なぜ注目されているか**: Auto mode自体は3月から段階的に対象プランを広げてきた「自分から`Shift+Tab`で切り替える」opt-in機能だったが、今回初めてプラン側の既定値そのものが変わる。信頼範囲は初期状態だと作業ディレクトリと現在リポジトリのremoteだけで、社内バケットや別リポジトリへの操作は`autoMode.environment`に自分で追加するまでブロックされる仕組み。
  - **使いどころ**: 経験の浅いメンバーが何も設定しないまま8/14を迎えると、確認なしでファイル編集やコマンド実行が進むようになる。レビュー前に自分とチームの`~/.claude/settings.json`・管理設定の`defaultMode`と`autoMode.environment`を確認し、AWSアカウントやproduction系ネームスペースの信頼範囲を先に設定しておくとよい。

- **[公式][実務][企画] Claude Code v2.1.224 — サブエージェント総数200件のセッション上限を撤廃** — https://code.claude.com/docs/en/changelog
  - **何が起きたか**: 8/7リリースのv2.1.224で、7月のv2.1.212で導入されていた「1セッションあたりサブエージェント生成200件まで」という上限が撤廃された。同時実行数20件・ネスト深度3などの上限は引き続き維持される。
  - **なぜ注目されているか**: この200件上限はもともと「暴走した委譲ループを止める」ための安全策として追加されたものだったが、Workflowで数十〜数百体のサブエージェントを回す長時間セッションや、一晩中ループを回す使い方では上限に達してセッションが新規エージェントの生成を拒否するようになっていた。
  - **使いどころ**: `/loop`やWorkflowで大きめのファンアウトを一晩中回すような運用をしているなら、これまで200件で止まっていたセッションが継続して動くようになる。「一晩中Claude Codeにやらせてみた」系のYouTube企画でも上限切れで止まる心配が減る。

- **[公式][企画] Claude Code v2.1.225 — SendMessageが相手からの連絡を待たず自分から会話を開始できるように** — https://code.claude.com/docs/en/changelog
  - **何が起きたか**: 8/8リリースのv2.1.225で、`SendMessage`が別マシン上のRemote Controlセッションに対して名前指定（`ListAgents`が`name [ref]`として表示）で会話を開始できるようになった。これまでは「相手から先にメッセージが来た場合にしか返信できない」仕様だった。
  - **なぜ注目されているか**: 8/7のv2.1.224でクロスセッションメッセージング自体は追加されたが、片方向（受信して初めて返信できる）の制約が残っていた。今回の変更で、あるセッションの発見や完了を別セッションへ能動的に伝える経路が初めて揃った。
  - **使いどころ**: 今すぐ必須ではないが、複数worktreeで並列に走らせているセッション同士に変更点を自動で伝え合わせる設計や、「複数のClaude Codeが相談しながら開発を進める」デモとしてYouTube企画にそのまま使える題材。
