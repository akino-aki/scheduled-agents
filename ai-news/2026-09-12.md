- **[公式][企画][実務] Claude Code v2.1.269 — `claude plugin eval`追加、Skill/プラグインをwith/without2アームで自動採点しCIゲートできるように** — https://code.claude.com/docs/en/plugin-evals
  - **何が起きたか**: v2.1.269（9/11）で`claude plugin eval`が追加された。プラグイン配下の`evals/`にprompt.mdとgraders/を置き、無料4種（regex・tool_used・tool_order・file_exists）と課金2種（llm・baseline、判定に別モデルを呼ぶ）の計6種のgraderで採点する。既定でプラグインあり/なしの2アームを各3回実行し、差分Δを算出、`--threshold`（既定1.0）でCIを落とせる。
  - **なぜ注目されているか**: これまでSkillやプラグインが「実際に効いているか」を測る手段はなく、9/4追加の`/skill-doctor`（既報）も「使われていないskillの検出」止まりだった。plugin evalは「そのskillが自然な言い回しで発火するか」「編集後やモデル更新後も挙動を保つか」「プラグイン無しより本当に優れているか」を初めて数値（Δ）で示せるようにした。
  - **使いどころ**: 自作skill/hookを増やしている今の運用に、CIでの回帰チェックとして組み込める。ただしeval実行・llm/baselineグレーダーは実モデル呼び出しでプラン利用枠かAPI課金を消費するので、まずは無料4種のgraderだけで小さく試すのが無難。

- **[公式][実務][企画] Claude Code v2.1.269 — `CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS`追加、Workflowの同時実行エージェント数上限（最大256）を引き上げ可能に** — https://github.com/anthropics/claude-code/releases/tag/v2.1.269
  - **何が起きたか**: v2.1.269で環境変数`CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS`（1〜256）が追加され、Workflowツールの同時実行エージェント数の上限を引き上げられるようになった。
  - **なぜ注目されているか**: これまでWorkflowの同時実行数は`min(16, CPUコア数-2)`という固定式で決まっており、5/30報告のissue #63938では10コア機で実質8並列までしか動かせず、50ファイル規模の一括レビューや5人以上のマルチ視点検証のような大規模fan-outがボトルネックになると指摘されていた。約3か月越しで環境変数による上限引き上げが実現した形。
  - **使いどころ**: 自作`/loop`やWorkflowで多数のサブエージェントを並列に回す構成を組んでいるなら、この変数を上げることで待ち時間を減らせる可能性がある。並列数を上げるほどAPIのレート制限やコストも増えるため、様子を見つつ段階的に上げるのがよい。

- **[公式][実務][企画] Claude Code v2.1.269 — Agent SDKセッションで要約できる過去の会話が無い場合「Prompt is too long」から復帰不能になる不具合を修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.269
  - **何が起きたか**: v2.1.269で、自動コンパクションが要約できる完全なやり取りを持たない場合（主にAgent SDKで非常に大きな初期プロンプトを渡すセッション）に「Prompt is too long」のまま永久に固まる不具合が修正された。
  - **なぜ注目されているか**: 「長すぎて圧縮できず、圧縮できないから長すぎるまま」というデッドロックは4/23報告のissue #52583をはじめ複数件が以前から報告しており、いったんこのエラーが出るとセッションを丸ごと放棄するしかなかった。
  - **使いどころ**: 個人開発のクイズアプリの出題登録〜公開自動化をAgent SDK経由で組む予定があるなら、大量の問題データなど大きめのプロンプトを一度に渡す場面でこれまで刺さっていた可能性のある落とし穴が塞がれたことになる。今すぐ影響が出ていないなら深追いは不要。

- **[公式][企画][実務] Claude Code v2.1.269 — Claude Code on the webのスケジュールroutineで、サブエージェント使用時に完了判定が早すぎてリトライがスキップされたり重複実行される不具合を修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.269
  - **何が起きたか**: v2.1.269で、Claude Code on the web上のスケジュールroutineがサブエージェントを使う場合、完了と誤判定されて失敗後のリトライがスキップされたり、逆に重複実行されたりすることがあった不具合が修正された。同リリースでは「単発スケジュールroutineがサーバー側の一時エラー後に2回実行される」不具合も別途修正されている。
  - **なぜ注目されているか**: バックグラウンドで動くサブエージェントの完了状態が実際の状態と食い違う系統の不具合は以前から報告例があり、7/23報告のissue #80684ではコンテナ再デプロイの完了通知が来ずポーリングで確認する羽目になり、5分の作業が約30分のトラブルシュートに化けたケースが記録されている。routineの信頼性に直結するこの種のバグが、今回on the web限定で名指しで修正された。
  - **使いどころ**: このダイジェストのようにスケジュールで無人実行するroutineの中でサブエージェント（Agent/Workflow）を使っているなら、これまで気づかないまま失敗が握りつぶされたり二重実行されたりしていた可能性がある。ただしCLIのheadless実行は今回の修正対象外（on the web限定）で、このダイジェスト自体はCLI経由のため直接の対象ではない。Cowork/on the web側でroutineを組む・組む予定があるなら確認する価値がある。
