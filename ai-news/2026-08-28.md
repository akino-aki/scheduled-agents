# 2026-08-28

> **収集環境について**: 本日も `zenn.dev` `aws.amazon.com` `techinformed.com` などへのアクセスが egress プロキシにより `EGRESS_BLOCKED` で、日本語の実践記事・活用事例、および一部のAWS公式情報の原文確認ができませんでした（3週間以上連続）。原文を直接読めた公式ソース（GitHub `anthropics/claude-code` releases、関連Issue、`code.claude.com` docs）から、背景まで裏取りできた4件を掲載します。すべて8/26・8/27リリースのv2.1.247・v2.1.248由来です。

- **[公式][実務] Claude Code v2.1.248 — `--restricted`フラグ追加、組み込みのコード実行系ツールとWebFetchを丸ごと外せるように** — https://github.com/anthropics/claude-code/releases/tag/v2.1.248
  - **何が起きたか**: 8/27リリースのv2.1.248で`--restricted`（環境変数`CLAUDE_CODE_RESTRICTED=1`）が追加された。コマンド・コードを実行する組み込みツールと`WebFetch`（`--tools`で明示指定しない限り）を除去し、ファイル系ツールは作業ディレクトリ内に限定、`bypassPermissions`は拒否、ユーザー/プロジェクト/ローカルの設定ファイルは無視する。
  - **なぜ注目されているか**: 5/26付のissue #62608は「`--allowedTools Write`だけを指定してもAskUserQuestion・Read・Skillなど組み込み20個のツールが動いてしまう」＝既存の`--allowedTools`は許可を積み増す方式で、本当の意味での制限にならないと指摘していた（duplicate close済みだが要望自体は残っていた）。今回の`--restricted`はその「本当に絞り込めるモード」への回答にあたる。
  - **使いどころ**: 経験の浅いメンバーに検証用・自動チェック用のセッションを触らせる際、`--restricted`でコード実行とネットワークアクセスを丸ごと外しておけば、許可ルールを個別に書くよりも安全側に倒せる。CI上で動かす専用エージェントの権限設計にも使える。

- **[実務] Claude Code v2.1.247 — サブエージェントがモデル404で即死しなくなり、セッションのフォールバックモデルチェーンを使うように** — https://github.com/anthropics/claude-code/releases/tag/v2.1.247
  - **何が起きたか**: 8/26リリースのv2.1.247で、サブエージェントが最初のAPI呼び出しでモデル404エラーに遭遇しても即座に落ちなくなり、セッション側のフォールバックモデルチェーンを使って継続するよう修正された。親セッションに返るエラーにも、エラー種別・ステータス・request id・モデル名が含まれるようになった。
  - **なぜ注目されているか**: 同系統の404は1月報告のissue #16115（`model: haiku`へのハードコードが疑われ、モデルを明示指定してもTask toolの全サブエージェントが動かなくなる重大バグとして報告）など、以前から繰り返し報告されてきた。8/27付ダイジェストで紹介した`modelPicker`（Bedrock/Vertex経由で複数モデルを切り替える設定）のような、指定モデルを切り替えて使う構成ほどこの404の影響を受けやすい。
  - **使いどころ**: Bedrock/Vertex経由で複数モデルを使い分けながらサブエージェントを多用する構成なら、指定モデルが一時的に使えない場合でもサブエージェントが落ちずに継続しやすくなる。エラー情報も詳しくなったため、原因調査の手間も減る。

- **[公式][実務][企画] Claude Code v2.1.248 — セッション間メッセージングがBedrock・Vertex・Foundry経由やテレメトリ無効環境でも使えるように** — https://github.com/anthropics/claude-code/releases/tag/v2.1.248
  - **何が起きたか**: 8/27リリースのv2.1.248で、同一マシン上のセッション間メッセージング（`SendMessage`/`ListAgents`）が、Bedrock・Vertex・Foundry経由の利用や、`DISABLE_TELEMETRY`等でテレメトリを無効化した環境でも動作するようになった。
  - **なぜ注目されているか**: 公式ドキュメントはこれまで、この機能がBedrock/Vertex/Foundry経由や一部のテレメトリ関連環境変数設定下では機能フラグ評価の都合で利用できないと明記していた。8月に入り段階的に拡張されてきたセッション間メッセージング（8/21・8/22・8/23・8/25付ダイジェストで既報）だが、この条件下だけは対象外のまま残っていた。
  - **使いどころ**: 社内プロキシ経由でBedrockを使う今の環境でも、複数worktreeのセッションを`@`メンションや`notify_when_idle`で連携させる使い方が初めて試せるようになる。「AIセッション同士が声を掛け合いながら開発する」というYouTube企画も、Bedrock環境のまま検証できる。

- **[企画] Claude Code v2.1.247 — `SendFeedback`ツール追加、セッション内の問題をClaudeが下書きしてから`/feedback`で送信可能に** — https://github.com/anthropics/claude-code/releases/tag/v2.1.247
  - **何が起きたか**: 8/26リリースのv2.1.247で、セッション中に問題が起きた際にClaude自身がフィードバック報告を下書きし、`/feedback`でユーザーが内容を確認してから送信できる`SendFeedback`ツールが追加された（`feedbackDrafts`設定でオフにできる）。
  - **なぜ注目されているか**: 6/4付のissue #65493は「Claude Codeから直接Anthropicへフィードバックを送る組み込みの手段がなく、外部チャンネルを探す必要がある」ことを、作業がブロックされるレベルの問題として報告していた（duplicate close済み）。今回、セッション内で完結する報告経路が用意された形。
  - **使いどころ**: 自作のskill/hook/routineがおかしな挙動をしたとき、その場でClaudeに下書きさせてから送信できるので、原因調査のついでに一次情報をAnthropicへ残しやすくなる。「Claude Codeにフィードバックを送ってみる」という工程自体を、YouTube企画の一コマにするのもよい。
