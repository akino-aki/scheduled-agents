> **収集環境について**: 本日も `zenn.dev` `qiita.com` などへのアクセスが egress プロキシにより `EGRESS_BLOCKED` で、日本語の実践記事・活用事例の原文確認ができませんでした（引き続き継続中）。検索で見つかった日本語ブログ記事の候補も、原文を直接読める形では見つからなかったか、内容が数か月前のものだったため今回は掲載を見送りました。原文を直接読めた公式ソース（GitHub `anthropics/claude-code` releases・関連Issue、`code.claude.com` docs）から、9/3リリースのv2.1.260・9/4リリースのv2.1.261のうち、背景まで裏取りできた5件を掲載します。

- **[公式][実務] Claude Code v2.1.260 — 前日v2.1.259の「Read() deny ruleをBash引数にも適用する」変更を撤回、`npm run build`や`cd … && grep`の誤ブロックを解消** — https://github.com/anthropics/claude-code/releases/tag/v2.1.260
  - **何が起きたか**: 9/3リリースのv2.1.260で、前日のv2.1.259が入れた「Read() deny ruleをBashの引数にも適用する」変更が撤回された。`Read(./**/build/**)`のようなdeny ruleがあると、あらゆるモードで`npm run build`が拒否され、`cd … && grep`がauto modeでも確認プロンプトを出すようになっていたことが理由。
  - **なぜ注目されているか**: 9/4付ダイジェストで報告した「Read() deny ruleがオプション引数値や`git diff`・コマンド連結をすり抜ける」不具合の修正が、その翌日には逆に正当な`npm run build`やgrepまで巻き込んで拒否する副作用を起こし、1日で撤回される事態になった。Bash deny ruleの抜け穴塞ぎが今月何度も続き、直したそばから別の不具合を生むきわどい綱引きが続いている実例といえる。
  - **使いどころ**: `.claude/settings.json`のRead() deny ruleでビルド成果物や`.env`を守っているなら、v2.1.259だけを使っていた1日の間は正当な`npm run build`などが巻き込まれて止まっていた可能性がある。v2.1.260以降に上げれば解消するが、「1つのリリースの修正内容を鵜呑みにせず、次のリリースで撤回されることもある」と経験の浅いメンバーに伝えておく価値がある。

- **[公式][実務][企画] Claude Code v2.1.260 — フルスクリーンモードに`/diff`で開ける差分パネルを追加、編集中の未コミット変更を会話の隣にリアルタイム表示** — https://github.com/anthropics/claude-code/releases/tag/v2.1.260
  - **何が起きたか**: v2.1.260で、フルスクリーンモード中に`/diff`を実行すると会話の隣に差分パネルが開き、Claudeが編集している未コミットの変更をリアルタイムで表示できるようになった。
  - **なぜ注目されているか**: これまでフルスクリーンモードで編集中の差分を見るには、会話を離れて別ターミナルやエディタで`git diff`を確認する必要があった。今回は会話画面から離れずに差分を追える動線が新たに用意された形になる。
  - **使いどころ**: 経験の浅いメンバーへのレビュー前に、自分がClaude Codeへ指示した変更が意図通りか別ターミナルへ切り替えずその場で確認できる。YouTube収録でも「会話とdiffを並べて見せる」画がそのまま作れるので、企画のネタとして使いやすい。

- **[公式][実務] Claude Code v2.1.260 — 括弧を含むパスの権限ルールが無視される不具合と、1つの不正な権限ルールで全ファイル編集が失敗する不具合を修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.260
  - **何が起きたか**: v2.1.260で2件の権限ルール不具合が修正された。①パスに括弧を含むEdit/Write/Read権限ルールがBashサンドボックス側で無効と判定され無視されていた問題、②閉じ忘れの`[`など解釈不能なパターンを含む権限ルールが1つあるだけで「Invalid regular expression」エラーとなり全ファイル編集が失敗していた問題。②は以後、該当ルールをそのまま文字列としてマッチさせるよう変更された。
  - **なぜ注目されているか**: settings.jsonの権限ルールの構文ミスが原因で設定全体が壊れるという系統の不具合は、2025年10月報告のissue #10096（コマンド引数に空白を含むdeny ruleがあると設定ファイル全体が黙って無視される）など以前から繰り返し報告されてきた。壊れ方が「静かに無視される」から「エラーで全編集が停止する」まで形を変えながら残っていたことになる。
  - **使いどころ**: 経験の浅いメンバーが書いたsettings.jsonのdeny/allowルールに、括弧を含むパスや閉じ忘れの`[`のような書き間違いが混ざると、これまでは気づかないうちに保護が効いていなかったり、逆に全員の編集が止まったりしていた。バージョンを上げつつ、レビューチェックリストに「権限ルールの括弧・角括弧の対応」を加えておくとよい。

- **[公式][実務][企画] Claude Code v2.1.261 — `/skill-doctor`追加、使われていないskillとそのコンテキストコストを表示して整理しやすく** — https://github.com/anthropics/claude-code/releases/tag/v2.1.261
  - **何が起きたか**: 9/4リリースのv2.1.261で`/skill-doctor`コマンドが追加され、読み込まれているが使われていないskillと、それぞれが消費しているコンテキストコストを表示して整理（pruning）しやすくする。
  - **なぜ注目されているか**: 公式ドキュメントによれば、skillの一覧はモデルのコンテキストウィンドウの1%を予算として説明文が詰め込まれ、予算を超えると呼び出し頻度の低いskillから静かに説明文が削られていく仕様になっている。これまでは既存の`/doctor`で一覧全体のコンテキストコストの概算は見えても、「どのskillが使われていないか」をピンポイントで示す手段はなかった。
  - **使いどころ**: 自作skill・hookを増やしていく運用をしているなら、`/skill-doctor`で使っていないskillを定期的に洗い出し、`skillOverrides`で`name-only`指定にする、あるいはfrontmatterを整理するといった対応がしやすくなる。個人開発・仕事用それぞれでskillが増えてきたタイミングで一度試す価値がある。

- **[公式][実務] Claude Code v2.1.261 — `bashOutputMaxChars`/`taskOutputMaxChars`追加、コマンド・バックグラウンドタスク出力をファイル退避前に最大128Kまでインライン表示可能に** — https://github.com/anthropics/claude-code/releases/tag/v2.1.261
  - **何が起きたか**: v2.1.261で設定`bashOutputMaxChars`と`taskOutputMaxChars`が追加され、コマンドおよびバックグラウンドタスクの出力を、ファイルへ退避する前に最大128,000文字までインラインで会話に表示できるようになった。
  - **なぜ注目されているか**: 9/1付ダイジェストで既報の通り、バックグラウンドタスクの出力が大きすぎると失敗通知自体がAPIリクエストサイズ上限を超えて会話が壊れる不具合がv2.1.252で修正されていた。その根には、issue #16591「バックグラウンドタスクの出力読み込みがトークン上限を無視してコンテキストを丸ごと使う」など以前からの出力サイズ制御不足の指摘があり、今回はその上限を利用者側が明示的に設定できる形で追加された。
  - **使いどころ**: CDK/ECSのデプロイやCloudFormationのスタックトレースのように出力が長くなりがちなコマンドをClaude Codeに実行させているなら、`bashOutputMaxChars`を上げておくと重要なログをファイル退避前にその場で読ませやすくなる。会話のコンテキストが肥大化しすぎるようなら、既定値のままにしておくのが無難。
