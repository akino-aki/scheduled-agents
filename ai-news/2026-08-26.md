- **[公式][実務] Claude Code v2.1.243 — `promptCacheTtl`/`subagentPromptCacheTtl`を追加、APIキー・クラウド経由ユーザーがプロンプトキャッシュを1時間保持できるように** — https://code.claude.com/docs/en/prompt-caching
  - **何が起きたか**: 8/25リリースのv2.1.243（およびv2.1.242）で、`promptCacheTtl`（会話本体）と`subagentPromptCacheTtl`（サブエージェント等）の設定が追加され、既定5分のプロンプトキャッシュ保持時間を`1h`に延ばせるようになった。
  - **なぜ注目されているか**: 公式ドキュメントによれば、Claudeサブスクリプションのプラン内利用では会話本体が既定で1時間キャッシュされる一方、APIキー・Bedrock/Vertex/Foundryなどクラウド経由やクレジット超過後の利用は、会話本体・サブエージェントともに既定5分のまま。5分を超えて考え込んだり離席したりするとキャッシュが切れ、再開時に全体を再計算する高いターンが発生する非対称な仕様だった。
  - **使いどころ**: 社内プロキシ経由でBedrockのClaude Codeを使いCDK/ECSの調査を長時間続けているなら、`promptCacheTtl: "1h"`の設定でキャッシュ切れの再計算コストを抑えられる。ただし1時間キャッシュは書き込み単価が上がるため、短時間で完結する作業が多いなら既定の5分のままの方が安い。

- **[公式][実務][企画] Claude Code v2.1.243 — `/usage`にLoopsの内訳を追加、`/loop`タスクごとのトークン消費が見えるように** — https://github.com/anthropics/claude-code/releases/tag/v2.1.243
  - **何が起きたか**: 同v2.1.243で、`/usage`にLoopsの内訳が追加され、`/loop`タスクごとの実行回数・合計トークン・1回あたりのトークン・最終実行時刻を確認できるようになった。
  - **なぜ注目されているか**: これまで`/loop`は動かした後にどのタスクがどれだけコストを消費しているか個別に把握する手段がなく、暴走したり無駄にやり取りが多いloopに気づきにくかった。今回はその可視化が`/usage`のコマンド1つで得られるようになった。
  - **使いどころ**: このダイジェスト自体も日次routineとして動いている。自作するskill/hook/routineが増えるほど、`/usage`のLoops内訳を定期的に見て、どれが無駄にトークンを食っているか棚卸しする習慣をつけるとよい。

- **[公式][実務] Claude Code v2.1.243 — サンドボックス化Bashへのプロンプトから許可済みネットワークホスト一覧を削除、未掲載ホストへも実際に試行するように変更** — https://github.com/anthropics/claude-code/releases/tag/v2.1.243
  - **何が起きたか**: 同v2.1.243で、サンドボックス化されたBashツールに渡すシステムプロンプトから許可済みネットワークホストの一覧が外れた。Claudeは許可リストを知らないまま実際にリクエストを試み、未許可のホストなら承認プロンプト（auto modeなら分類器の判断）がその場で挟まる仕組みに変わった。
  - **なぜ注目されているか**: リリースノートは「未掲載のホストを遮断済みだと誤って思い込むのを防ぐため」と明記している。従来はプロンプトに許可ホスト一覧が載っていたため、Claudeがそこに無いホストへの接続を試す前から諦め、本来通せるはずの正当な通信まで失敗扱いにしていた可能性がある。
  - **使いどころ**: マルチアカウント環境で`sandbox.network.allowedDomains`を細かく設定しているなら、これまで「一覧に無いから」と諦められていた正当な通信が試行されるようになる。承認プロンプトや`allowedDomains`自体の仕組みは変わらないため、経験の浅いメンバーへのレビュー観点は従来通りでよい。

- **[公式][実務] Claude Code v2.1.243 — バックグラウンドのサブエージェントが、自身の最後のバックグラウンドBashタスク完了後に目を覚まさない不具合を修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.243
  - **何が起きたか**: 同v2.1.243で、バックグラウンドで動くサブエージェントが、自分が投げていた最後のバックグラウンドBashタスクの完了後に反応を再開しない不具合が修正された。
  - **なぜ注目されているか**: バックグラウンド作業の完了検知は8月に入って`/goal`の30分チェックイン導入（8/17のv2.1.234）から段階的な間隔延長（8/21のv2.1.239）まで続けて手が入ってきた領域（8/18・8/23・8/25付ダイジェストで既報）。今回はその一段下、サブエージェント自身がバックグラウンドタスクの完了に気づけず止まったままになるケースへの対処で、同じ「待ち」の信頼性改善の一環。
  - **使いどころ**: CDK/ECSのデプロイ待ちやビルド待ちをサブエージェントにバックグラウンドで任せる設計をしているなら、完了後に反応が返らず止まって見える事故が減る。`/loop`やWorkflowでサブエージェントを多用する運用ほど効いてくる。
