- **[公式][実務] Claude Code v2.1.234 — 組み込み `claude-api` skill のコンテキストコストを 200k+ → 約25k トークンに削減** — https://code.claude.com/docs/en/changelog
  - **何が起きたか**: 8/17リリースのv2.1.234で、Claude API / Anthropic SDK のリファレンスを提供する組み込み skill `claude-api` が、参照ドキュメントを必要になった時点で読み込む方式に変わり、ロード時のコンテキストコストが200k超から約25kトークンへ下がった。
  - **なぜ注目されているか**: この skill は「プロンプトに Claude / Anthropic / モデル名が出てきたら開く」という広い発動条件を持つため、意図せず読み込まれやすい。6/17報告のissue #69179では、`claude-api` skill をロードした直後にコンテキスト使用量が24.2k→42.4kに跳ね上がり、200kウィンドウの21%しか使っていないのに "Context limit reached" が出る状態が報告されている（現在もOpen）。
  - **使いどころ**: Next.jsクイズアプリのAI出題判定まわりをClaude Codeに実装させるときは、この skill がほぼ確実に発動する。これまで「API周りの相談を始めた途端にコンテキストが苦しくなる」体感があったなら、v2.1.234以降で改善しているはず。

- **[公式][実務] Claude Code v2.1.234 — MCP の診断出力に解決済みシークレットが平文で出る問題を修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.234
  - **何が起きたか**: 同v2.1.234で、MCPのスコープ競合warningが `${VAR}` の設定形のまま表示されるようになり、接続失敗の詳細もサーバーのoriginのみを出すよう変更された。従来はこれらの診断出力に実際のトークン値が展開されて出ていた。
  - **なぜ注目されているか**: MCP設定まわりのシークレット露出は繰り返し報告されてきた系統の問題。5/8報告のissue #57131では、`claude mcp remove` / `claude mcp add` が `.mcp.json` を読み書きする共通経路で `${VAR}` を実値に展開して書き戻してしまい、その後 `git commit -am` すると本番クレデンシャルがそのままコミットされうる、という不具合が報告されていた（Closed）。issue #58043でも、設定ファイルをRead/catすると会話トランスクリプトにAPIキーが永続的に残る点が指摘されている。
  - **使いどころ**: マルチアカウント環境でMCPサーバーに `${AWS_...}` 系の環境変数を渡している構成なら、MCPの接続不良を調査する場面で診断ログをそのままSlackやIssueに貼っても値が漏れにくくなった。経験の浅いメンバーに切り分けを任せるときの事故が1つ減る。

- **[公式][実務] Claude Code v2.1.234 — auto mode の長時間セッションで、compact 後にサンドボックスコマンドのネットワークアクセスを繰り返し再確認・拒否する不具合を修正** — https://code.claude.com/docs/en/changelog
  - **何が起きたか**: 同v2.1.234で、auto modeの非常に長いセッションにおいて、会話がcompactされた後にサンドボックス実行コマンドのネットワークアクセスを何度も再チェックし、拒否してしまう挙動が修正された。
  - **なぜ注目されているか**: auto modeは8/14からPro/Max/Teamの新規セッションで既定になった（8/9付ダイジェストで既報）ばかりで、影響範囲が一気に広がったタイミングの修正。compact後に権限判断の文脈が失われて挙動が変わる問題は、issue #32029（auto-compactのプロンプトが「ユーザーに聞かず続行せよ」と指示するため自己承認が起きる）など、compactと権限まわりの相互作用として以前から報告があった領域。
  - **使いどころ**: CDK/ECSのビルドやテストを1セッションで長時間回していて、途中から `npm install` や API 取得が理由不明で拒否され始めた経験があるなら、v2.1.234で解消している可能性が高い。routineや `/loop` で無人運用しているセッションほど効く。

- **[公式] Claude Code v2.1.235（8/18リリース、現時点の最新）— クラウドセッションのメモリ/CPU使用率を改善、スペルチェックを追加** — https://github.com/anthropics/claude-code/releases/tag/v2.1.235
  - **何が起きたか**: 8/18リリースのv2.1.235で、`/ultrareview` や `/autofix-pr` などクラウド側で走るセッションのメモリ・CPU使用率が改善された。あわせて、`aspell` / `hunspell` / `ispell` がインストールされていればプロンプト入力中の綴り間違いを下線表示するオプションが追加。macOS/Linuxネイティブビルドの組み込み`grep`も改善されている。
  - **なぜ注目されているか**: `/ultrareview`（バグ探索エージェント群をクラウドで走らせ、結果をCLI/Desktopに返す機能）は4/20週にpublic research previewとして公開され、4/27週に`claude ultrareview`でCI・スクリプトからも呼べるようになった機能。`/autofix-pr`は4/6週にターミナルからPR自動修正を有効化するコマンドとして追加された。どちらもクラウド実行が前提のため、リソース効率が直接使い勝手に効く。
  - **使いどころ**: 経験の浅いメンバーのPRレビュー品質を揃える用途で`/ultrareview`をCIに組み込む構成を検討しているなら、まずv2.1.235に上げてから評価するとよい。今すぐ導入しないなら急ぎの更新ではない。
