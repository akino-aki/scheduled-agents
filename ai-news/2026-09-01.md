- **[公式][実務] Claude Code v2.1.252 — 「Always allow」の選択が、`.claude/settings.local.json`がまだ存在しないプロジェクトで保存されない不具合を修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.252
  - **何が起きたか**: 8/31リリースのv2.1.252で、権限確認ダイアログの「Always allow」を選んでも、そのプロジェクトに`.claude/settings.local.json`がまだ存在しない場合は選択が保存されない不具合が修正された。
  - **なぜ注目されているか**: 「Always allowを選んでも次回また聞かれる」という不満は2025年11月報告のissue #11172をはじめ以前から繰り返し報告されてきたが、同issueは原因を特定できないまま「Closed as not planned」で終わっていた。今回はそのうち「設定ファイルがまだ無い新規プロジェクト」という具体的な条件に絞って原因が特定・修正された形。
  - **使いどころ**: CDK/ECSの新しいリポジトリや個人開発のクイズアプリなど、まだ`.claude/settings.local.json`が無いプロジェクトを始めるとき、あるいは経験の浅いメンバーに新規プロジェクトを触らせるときに影響する。バージョンを上げておけば、初回の権限設定が想定通り保存されているか確認する手間が減る。

- **[公式][実務][企画] Claude Code v2.1.252 — バックグラウンドタスクの失敗出力が非常に大きい場合、通知がAPIリクエストサイズ上限を超えて会話が壊れる不具合を修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.252
  - **何が起きたか**: 同v2.1.252で、バックグラウンドタスクの失敗時（リリースノートの例では「ディスクフルによるgitエラー」など）に出力が非常に大きいと、その完了通知自体がAPIリクエストサイズの上限を超えてしまい会話が続けられなくなる不具合が修正された。
  - **なぜ注目されているか**: バックグラウンドタスクの出力が大きすぎてトークン上限を超えメイン会話が詰まる、という系統の問題は以前から報告されており（issue #39337「バックグラウンドタスク完了後、出力ファイルの読み込みがトークン上限を超えるとメインスレッドが停止しうる」、issue #16591「バックグラウンドタスクの出力読み込みがトークン上限を無視してセッションのコンテキストを丸ごと使う」）、今回はそのうち「失敗通知自体がAPIリクエストサイズ上限を超える」という具体的なケースに手が入った形。
  - **使いどころ**: このダイジェスト自体を含め、routineや`/loop`でCDK/ECSのデプロイ・テストをバックグラウンド実行させる運用をしているなら、失敗時に大量のエラーログを吐くタスク（ディスクフルやCloudFormationの大きなスタックトレースなど）が原因で会話ごと壊れる事故が減る。心当たりがあればバージョンを上げておく価値がある。

- **[公式][企画] Claude Code v2.1.252 — Claude Desktop/VS Code拡張がホストするRemote Controlセッションが、接続劣化時にツール完了後も数分間固まる不具合を修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.252
  - **何が起きたか**: 同v2.1.252で、Claude DesktopやVS Code拡張がホストするRemote Controlセッションが、claude.aiへの接続が（完全な切断ではなく）劣化した状態のときにツール呼び出しが完了しても数分間反応が固まる不具合が修正された。
  - **なぜ注目されているか**: Remote Controlの反応停止・ハング自体は、10分程度の利用後に固まる報告（issue #52860）や、途中で無言のまま反応しなくなる報告（issue #51267）など以前から繰り返し報告されてきた領域。今回はそのうち「完全切断ではなく接続が劣化しただけのケース」という、より発見しにくいパターンに絞って修正された。
  - **使いどころ**: CDK/ECSのデプロイ待ちをスマホやVS CodeからRemote Controlで覗く運用をしているなら、電波が弱い場所などで「反応が返らず固まった」と感じた原因の一つが解消されたことになる。YouTube収録中にRemote Controlの安定性を実演するネタとしても使える。
