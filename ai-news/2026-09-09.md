- **[公式][実務] Claude Code v2.1.265 — 非対話セッション（`-p`/stream-json/Agent SDK/クラウド）で`cd`がターン間で永続化されない不具合を修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.265
  - **何が起きたか**: 9/8リリースのv2.1.265で、`-p`のstream-json入出力やAgent SDK、クラウドセッションなど非対話セッションにおいて、Bashツールの子プロセスが`cd`した先ではなく毎回`/`から実行されてしまう不具合が修正され、ターン間で作業ディレクトリが引き継がれるようになった。
  - **なぜ注目されているか**: 4/12報告のissue #46985は、Node/Bun/PythonからCLIをサブプロセスとして起動し`cwd`を渡しても、Bashツールの子プロセスだけは`/`固定で動いてしまう再現性の高いバグだと報告していた。CLI自体の初期化cwdは正しく認識されるのにBashツールだけずれるという、Agent SDK連携を組む開発者を継続的に悩ませてきた問題だった。
  - **使いどころ**: 個人開発のクイズアプリの出題登録〜公開自動化をAgent SDK経由やheadlessの`-p`で組んでいるなら、これまで`cd`が効かずフルパスを渡す回避策が要らなくなる可能性がある。バージョンを上げて一度動作確認する価値がある。

- **[公式][企画][実務] Claude Code v2.1.265 — Workflowのコンテナ再起動後の実行再開に対応、実行履歴（journal）が無い場合は黙って最初からやり直さずエラー表示に** — https://github.com/anthropics/claude-code/releases/tag/v2.1.265
  - **何が起きたか**: v2.1.265で、Workflow（マルチエージェント）実行がコンテナ再起動後も`resumeFromRunId`で再開できるようになり、実行ジャーナルが見つからない場合は明確なエラーメッセージを出すよう変更された。
  - **なぜ注目されているか**: 6/6報告のissue #65796は、長時間セッションが自動コンパクションでセッションIDが変わると、完了済みフェーズの実行履歴（当時journal.jsonlが約61KB）に新セッションからアクセスできなくなり、警告もないままフェーズ1から黙って全部再実行され8時間分のトークンが無駄になった、と報告していた。
  - **使いどころ**: `/loop`やWorkflowで長時間の多段パイプラインを組んでいるなら、再開に失敗しても気づかず費用だけ溶かす事故が減る。YouTube収録でWorkflowの多段処理をデモする際、「再開が壊れていたら分かるようになった」という小ネタにもなる。

- **[公式][実務] Claude Code v2.1.265 — SendMessageでサブエージェント/teammateを再開する際、最初の呼び出しだけ必ずキャッシュミスしていた不具合を修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.265
  - **何が起きたか**: v2.1.265で、フォアグラウンド起動したサブエージェントやteammateをSendMessageで再開する際にツールリストやシステムプロンプトのプリフィックス差異でキャッシュ再利用が壊れていた不具合が修正された。
  - **なぜ注目されているか**: 4/7報告のissue #44724は、`Agent()`と`SendMessage()`でsystemブロック冒頭の名乗り文言（「Claude Code」か「Claude agent」か）が違うだけでキャッシュプリフィックス全体が無効化され、再開1回目は必ずcache_read=0のフルミスになると報告していた。Opus・大きめコンテキストの試算ではキャッシュヒット時$0.075に対しミス時$0.75と、再開のたびに10倍のコストがかかっていた計算になる。
  - **使いどころ**: CDK/ECSレビュー用のサブエージェントやteammateとSendMessageでやり取りしながら使う運用をしているなら、これまで気づかず再開のたびに割高な課金をしていた可能性がある。バージョンを上げるだけで効く改善。

- **[公式][実務][企画] Claude Code v2.1.265 — ツール結果のディスク保存に1GBの上限を追加、暴走したタスク出力が数分でディスクを埋め尽くす事故を防止** — https://github.com/anthropics/claude-code/releases/tag/v2.1.265
  - **何が起きたか**: v2.1.265で、ツール結果をディスクへ保存する際の容量に1GBの上限が新設され、超過分は切り詰められ会話内にプレビュー表示されるようになった。
  - **なぜ注目されているか**: 4/1報告のissue #41737は、バックグラウンドタスクの出力ファイルにClaude Code自身のミニ化されたバンドルコードが繰り返し書き込まれ続け、12分で232GB・合計278GBに達し`no space left on device`でシステム全体の書き込みが止まった重大バグを報告していた。同様の暴走（107GB/3分、350GB/1セッションなど）が複数回報告されており、ディスクが0バイトになると設定・認証情報が破損する二次被害も伴っていた。
  - **使いどころ**: 自作routineやバックグラウンドタスクを多用する運用をしているなら、ある日突然ディスクが埋まって設定が壊れる、という理論上の事故への備えが一段強くなる。YouTube収録用に「Claude Codeが自分の身を守る仕組み」のネタとしても使える。
