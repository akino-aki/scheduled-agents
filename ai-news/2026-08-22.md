- **[公式][実務] Claude Code v2.1.236 — `ANTHROPIC_DEFAULT_MODEL` 環境変数を追加、`/model`の選択が意図せず上書きされなくなる** — https://github.com/anthropics/claude-code/releases/tag/v2.1.236
  - **何が起きたか**: 8/19リリースのv2.1.236で、新規セッションの初期モデルだけを指定する`ANTHROPIC_DEFAULT_MODEL`環境変数が追加された。`--model`・`ANTHROPIC_MODEL`・設定ファイルの`model`など他の指定が無いときだけ適用される。
  - **なぜ注目されているか**: 公式ドキュメントによれば、従来の`ANTHROPIC_MODEL`は「セッション中に`/model`で別モデルへ切り替えて保存しても、次回起動時には環境変数側のモデルへ戻ってしまう」挙動だった。新しい変数は初期値だけを決め、`/model`で保存した選択は次回以降も優先されるようになる。
  - **使いどころ**: CDK/ECS用の調査セッションとクイズアプリ開発用とでモデルを使い分けつつ、その場ごとに`/model`で選び直したいなら、`ANTHROPIC_MODEL`の代わりに`ANTHROPIC_DEFAULT_MODEL`を設定しておくと選択が上書きされなくなる。

- **[公式][実務] Claude Code v2.1.239 — Bedrockをプロキシ経由で使うと、ストリーミング応答が課金APIコールをサイレントに倍加させていた不具合を修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.239
  - **何が起きたか**: 8/21リリースのv2.1.239で、プロキシがレスポンスのContent-Typeヘッダを書き換える環境でのBedrockストリーミングが修正された。リリースノート原文は「各ターンをストリーミングなしで再実行することで、課金対象のAPIコールをサイレントに倍加させていた("silently doubled billed API calls")」と明記している。
  - **なぜ注目されているか**: エラーは表示されず、裏で同じターンが2回課金される形で進行するため、コスト超過に気づきにくいタイプの不具合だった。社内プロキシやゲートウェイ経由でBedrockを使う構成ほど影響を受けやすい。
  - **使いどころ**: マルチアカウント環境で社内プロキシ経由のBedrockを使っているなら、v2.1.239へのアップデートで想定外のコスト超過リスクが減る。心当たりがあるなら過去の利用量ログと突き合わせておく価値がある。

- **[公式][実務] Claude Code v2.1.239 — Bedrock + SSOプロファイル利用時、HTTPSプロキシ配下だと起動時にハングする不具合を修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.239
  - **何が起きたか**: 同v2.1.239で、`awsAuthRefresh`を有効にしてBedrock + AWS SSOプロファイルを使う構成において、HTTPSプロキシ配下だと起動時のクレデンシャル事前チェックが`HTTPS_PROXY`を参照せずハングしていた不具合が修正された。
  - **なぜ注目されているか**: AWS SSOでプロファイルを切り替えつつ社内プロキシ経由で通信する構成は、マルチアカウント運用でよくある形。今回はその組み合わせに限ってクレデンシャル事前チェックの通信経路が塞がれていたことが分かる。
  - **使いどころ**: `aws sso login`でプロファイルを切り替えながらHTTPSプロキシ配下でClaude Code + Bedrockを使っている場合、起動が固まっていた原因はこれだった可能性がある。v2.1.239へ上げて解消しているか確認するとよい。

- **[公式][実務][企画] Claude Code v2.1.239 — フルスクリーンモードで、ターミナルにフォーカスを戻すだけのクリックが権限プロンプトへの回答として誤処理される不具合を修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.239
  - **何が起きたか**: 同v2.1.239で、フルスクリーンモード中に他ウィンドウからターミナルへクリックでフォーカスを戻しただけなのに、そのクリック位置に権限プロンプトのボタンがあると回答・押下として処理されてしまう不具合が修正された。
  - **なぜ注目されているか**: 確認画面が誤動作したことを示す表示は特になく、フォーカスを戻すつもりのクリックが「はい」やボタン押下として通ってしまう類の不具合で、破壊的なgit操作などの確認プロンプトが出ている場面ほどリスクが大きい。
  - **使いどころ**: 画面収録しながら別ウィンドウ（ブラウザや資料）とターミナルを行き来するYouTube企画のワークフローでは、フルスクリーンモード中にまさに起きやすいパターン。バージョンを上げつつ、権限プロンプト表示中はクリックでの復帰を避ける癖をつけておくとよい。
