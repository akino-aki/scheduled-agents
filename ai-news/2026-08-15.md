- **[公式][実務][企画] Claude Code v2.1.232 — Subagent forking が既定でオンに（4/22のopt-inフラグから昇格）** — https://github.com/anthropics/claude-code/releases/tag/v2.1.232
  - **何が起きたか**: 8/13リリースのv2.1.232で、`subagent_type: "fork"`のサブエージェントが会話全体とプロンプトキャッシュを継承する「フォーク」動作が既定でオンになった。あわせて、対話セッション内でteammateでないサブエージェントの生成が既定でバックグラウンド実行になる。無効化は`CLAUDE_CODE_FORK_SUBAGENT=0`。
  - **なぜ注目されているか**: フォークサブエージェントは4/22のv2.1.117で`CLAUDE_CODE_FORK_SUBAGENT=1`によるopt-in機能として外部ビルドに追加されて以来、約4ヶ月間は自分で有効化しないと使えない機能だった。今回それが全ユーザーの既定挙動に格上げされた。
  - **使いどころ**: `/loop`やWorkflowで文脈を引き継ぎたいサブエージェントを回している場合、設定変更なしで会話履歴とキャッシュが引き継がれるようになる。逆に「毎回まっさらな文脈で調査させたい」用途なら、`CLAUDE_CODE_FORK_SUBAGENT=0`で明示的に戻す必要がある点に注意。

- **[公式][実務] Claude Code v2.1.232 — nested git repositoryの信頼継承バグとsandbox.ripgrepのプロジェクト設定オーバーライドを修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.232
  - **何が起きたか**: 同v2.1.232で、親ディレクトリの信頼設定を子のgitリポジトリがそのまま継承してしまい、個別の信頼確認なしで動作していた不具合が修正され、リポジトリごとに信頼確認が必須になった。また`sandbox.ripgrep`はユーザー設定・管理設定・`--settings`からのみ有効になり、プロジェクト設定（リポジトリ同梱の`.claude/settings.json`）からの上書きができなくなった。
  - **なぜ注目されているか**: 前者は、信頼済みのモノレポ配下にネストした別リポジトリ（サブモジュール等）を開くと、そのリポジトリ自体は確認していないのに信頼済み扱いになってしまう抜け穴だった。後者は、8/8付ダイジェストで既報の「AWSキーの再署名設定はプロジェクト設定からは効かない」という方針と同じ系統で、リポジトリに同梱される設定ファイル経由でサンドボックスの検索バイナリを差し替えられる余地を塞いだ。
  - **使いどころ**: マルチアカウント環境でモノレポやサブモジュールを扱っている場合、これまで気づかず信頼していたネストリポジトリがあれば今回の更新で改めて確認を求められる。外部から取り込むリポジトリのプロジェクト設定を無条件に信用しない、という方針を保つうえで地味に効く修正。

- **[公式][実務] Claude Code v2.1.232 — `/code-review`がhigh/xhigh/max effortでもバックグラウンド実行に統一** — https://github.com/anthropics/claude-code/releases/tag/v2.1.232
  - **何が起きたか**: v2.1.218で`/code-review`は低〜中effortから会話を占有しないバックグラウンドサブエージェント実行に変わっていたが、v2.1.232でhigh・xhigh・maxの高effortレベルもバックグラウンド実行に揃えられた。
  - **なぜ注目されているか**: これまで高effortでレビューを走らせると会話がその間ブロックされ、他の作業と並行しづらかった。今回で全effortレベルの挙動が統一され、重いレビューを回している間も同じセッションで別作業を進められるようになった。
  - **使いどころ**: 経験の浅いメンバーのPRを`/code-review high`や`max`でじっくり見る運用をしているなら、レビュー実行中に会話がブロックされなくなり、待ち時間に他のPRの確認を並行して進められる。

- **[公式][企画] Claude Code v2.1.232 — プロンプトで`@`と打つだけで別セッションに話しかけられるように** — https://github.com/anthropics/claude-code/releases/tag/v2.1.232
  - **何が起きたか**: 同v2.1.232で、プロンプト中に`@`と打って名前を指定すると、Claudeが`SendMessage`を使ってその名前の別セッションへ直接メッセージを送れるようになった。同一マシン上で同じ名前のセッションが複数あると自動で`name-word-word`のような一意な名前に変わる。
  - **なぜ注目されているか**: 8/7のv2.1.224でセッション間メッセージング自体が入り、8/8のv2.1.225で片方向だった制約が外れて自分から会話を開始できるようになった（8/8・8/9付ダイジェストで既報）。今回`@`メンションが加わり、`ListAgents`で名前を調べなくてもプロンプトから直接呼びかけられるようになった。
  - **使いどころ**: 複数worktreeで並列にセッションを走らせて相互に進捗を伝え合う設計や、「複数のClaude Codeが会話しながら開発を進める」デモがより手軽に組めるようになった。YouTube企画のネタとして引き続き温めておくとよい。
