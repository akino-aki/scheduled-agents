- **[実務][企画] issue #96064 — skillを更新してもセッションには古いバージョンが無言で配信され続ける不具合（9/22報告, 未修正, 深刻度「サイレントな誤出力」）** — https://github.com/anthropics/claude-code/issues/96064
  - **何が起きたか**: 自作skill（正規表現を修正し`2026-0917b`→`2026-0921a`にバージョンを上げたもの）を更新・再インストールしても、Settings画面には新バージョンが表示される一方、実際にセッションへ配信されるのは更新前のコードだった。5回以上のセッション、3回の再インストール、アプリ完全再起動、プラグインキャッシュディレクトリの手動削除でも再現し、削除後もアプリが同一ハッシュで旧バージョンを復元してしまう。エラーは一切出ず、処理は正常終了（exit code 0）するが、報告者の実例では35件以上のデータが欠落していた。
  - **なぜ注目されているか**: 原因はSettings画面が参照するIndexedDBには正しい新バージョンが入っているのに、実行時にセッションへ渡す配信ツリー（`claude-hostloop-plugins`配下）には古いバージョンのコピーがそのまま残り続けるという、表示と実行の経路が食い違う構造的な問題。バージョン番号や画面表示を信じても実際に動いているコードは古いままという、確認のしようがない失敗モードになっている。
  - **使いどころ**: 自作skillを日常的に更新しているなら、更新後は表示だけでなく実際の出力結果を必ず一度確認する習慣をつけた方がよい。直るまでの回避策は、`.skill`バンドルを自分で管理するパスに展開してスクリプトを直接呼び出す方法（配信機構を経由しない）。クイズアプリの自動化に組み込むskillでこの症状が出ると、採点ロジックの修正が反映されないまま出題が進む恐れがある。

- **[実務][企画] issue #96318 — PreToolUse/PostToolUseフックの`matcher: "Skill"`が再び効かなくなる回帰（9/23報告, 未修正）— 同種のバグは4月に一度「対応しない」でクローズ済み** — https://github.com/anthropics/claude-code/issues/96318
  - **何が起きたか**: `"matcher": "Skill"`を指定したフックがskill呼び出し時に発火しなくなったと報告された。報告者は詳細な再現手順を書かず、4月に「not planned」としてクローズされた同種の回帰issue #47307（v2.1.59では動いていたのがv2.1.92で壊れ、ドキュメントからも記述が消えた）を指して「あなたたちが既にクローズした問題を見ろ」と述べている。
  - **なぜ注目されているか**: #47307は代替手段の提示もないまま「意図的な仕様変更」として片付けられていたが、今回はそれとは別に一度直っていたはずの挙動が再度壊れたという内容で、同じ場所が繰り返し壊れている。9/22付の本ダイジェストで報告した「PreToolUse hookの`if`フィールドがSkill呼び出しにマッチしない」issue #95819と合わせると、Skillツールに対するフック連携の足回り自体が全般的に不安定な状態が続いている。
  - **使いどころ**: skill/hookを組み合わせた自作routineで`matcher: "Skill"`に依存する処理があるなら、現状は信用せず、フックスクリプト側で`tool_input.skill`を自前チェックする実装に倒しておく方が安全。新しい自動化を組む際も、まず`matcher: "Skill"`が実際に発火するか手元で確認してから設計するとよい。

- **[公式][実務] Claude Code v2.1.281（9/23）— MCPサーバーが会話途中で切断・再接続待ちになるとprompt cacheが失われる不具合、PreToolUse hookがMCP接続待ちをスキップしていた不具合を修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.281
  - **何が起きたか**: v2.1.281のリリースノートに「Fixed the prompt cache being lost when an MCP server disconnects mid-conversation, or is still connecting after a resume, while tool search is off」「Fixed `mcp_tool` hooks on blocking events (PreToolUse and similar) being skipped while their MCP server was still connecting; they now wait for it, up to the MCP connect timeout」と明記されている。v2.1.283ではさらに「a brief HTTP 404 from a stateless remote MCP server（プロキシの再デプロイ中など）leaving that server unusable for the rest of the session while still shown as connected」という、一時的な404で以後そのMCPサーバーが使えなくなる不具合も修正された。
  - **なぜ注目されているか**: いずれも「MCPサーバーが一瞬不安定になっただけで、以後の会話全体（キャッシュ・フック・ツール呼び出し）に静かに悪影響が残る」という同系統の失敗モードで、リリースノート上は3つの別々の修正だが根はMCP接続のライフサイクル管理の甘さという共通点がある。
  - **使いどころ**: クイズアプリの出題登録〜公開自動化やAgent SDKで自作MCPサーバーを動かしているなら、これまで原因不明のprompt cache再構築やフックの無効化に悩まされていた場合、v2.1.281以降への更新で解消している可能性がある。自作MCPサーバーがデプロイ中に一瞬404を返す構成なら、v2.1.283への更新で「以後セッション中ずっと使えなくなる」事故も避けやすくなる。

- **[公式][実務] Claude Code v2.1.281（9/23）— auto modeのclassifier審査が読み取り専用・サンドボックス化されたコマンドにも拡大、フラグが立てば実行前にブロックされるように** — https://github.com/anthropics/claude-code/releases/tag/v2.1.281
  - **何が起きたか**: v2.1.281のリリースノートに「Changed auto mode so that, where its classifier review runs server-side, read-only and sandboxed shell commands also wait for that review and are blocked when it flags them」と明記された。従来は読み取り専用コマンドやサンドボックス実行が許可の速いパスだったが、サーバー側classifierレビューの対象がその範囲まで広がった。
  - **なぜ注目されているか**: 9/27付の本ダイジェストで報告したissue #94740（PreToolUse hookが"allow"と判定してもauto modeのclassifierに再送されブロックされうる、という非対称仕様への改善要望）は、読み取り専用コマンドが今回の変更で新たにclassifier審査の対象に加わったことで、影響範囲がさらに広がる可能性がある変更でもある。安全性向上の方向ではあるが、無人routineの「止まらず進む」という前提と摩擦を生みやすい部分が拡大した形。
  - **使いどころ**: auto modeで無人routineを組んでいて、これまで速く通っていた読み取り専用コマンド（`cat`や`ls`相当のBash呼び出しなど）が急に止まるようになった場合、この変更が原因の可能性がある。フックの"allow"判定をclassifierが上書きする問題（#94740）が未解決な間は、厳密に自動実行させたい読み取り専用コマンドも含めて`permissions.allow`のルール側に明示しておく方が安全。
