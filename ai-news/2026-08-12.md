- **[公式][実務] Claude Code v2.1.228 — Write toolが新モデルで無読み込み上書き可能に／claude.ai同期スキルのセキュリティ強化** — https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md
  - **何が起きたか**: 8/11リリースのv2.1.228で、新しいモデルはEditツールと同様、セッション内で事前に読み込まなくてもWrite toolで既存ファイルを上書きできるようになった（旧モデルは引き続き読み込みが必須）。同時に、claude.aiから同期されるスキルにセキュリティ強化が入り、ローカルコマンドやMCPプロンプトを偽装（shadow）できなくなったほか、説明文のサニタイズ、実行時の`!`コマンド実行・`@`ファイル展開の無効化が行われた。
  - **なぜ注目されているか**: Write toolはこれまで「事前Read必須」が誤上書きを防ぐ安全網として機能していたが、新モデルではその制約が外れる仕様変更。スキル同期側の変更は、外部から取り込んだスキルがローカル環境のコマンドやMCPプロンプトになりすませてしまう脆弱性クラスへの対策。
  - **使いどころ**: 8/14からAuto modeが既定化され確認なし操作が増えるタイミングと重なる。経験の浅いメンバーには「Write toolはもう事前確認なしで上書きされうる」ことをレビュー前に共有しておくとよい。claude.aiのスキル同期を使っている場合、追加対応は不要（自動適用）。

- **[公式][実務] Claude Code v2.1.227 — claude-code-actionでBashコマンドが全滅するバグを修正** — https://code.claude.com/docs/en/changelog
  - **何が起きたか**: 8/10リリースのv2.1.227で、GitHub-hostedランナー上の`claude-code-action`に`allowed_non_write_users`を設定していると、Bashコマンドが軒並み失敗していた不具合が修正された。
  - **なぜ注目されているか**: `allowed_non_write_users`は書き込み権限を持たない外部コントリビューターにもレビューなどのワークフローをトリガーさせるための設定。この設定を使うワークフローに限ってBashが実行不能になるという、原因の切り分けがしにくい不具合だった。
  - **使いどころ**: GitHub Actions上で`claude-code-action`によるPRレビュー自動化をしていて`allowed_non_write_users`を使っている場合、v2.1.227未満で原因不明のBash失敗に当たっていたなら今回の更新で解消する。
