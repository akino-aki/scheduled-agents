- **[公式][企画] Claude Code v2.1.287（10/1）— 「Claude Mods」公開。プラグインがJavaScript/TypeScriptでClaude Code自体の挙動・画面描画に踏み込めるようになり、第一弾として「You should know」（見落とし検知エージェント）が標準搭載** — https://github.com/anthropics/claude-code/releases/tag/v2.1.287
  - **何が起きたか**: v2.1.287でmod機構が正式公開された。modはプラグインの一種で、ツール呼び出し・プロンプト送信・画面描画などのイベントに対しJavaScript/TypeScriptの関数（hook）を登録でき、既存のUIを書き換えたり、ツール呼び出しを横取りして承認・拒否したりできる。標準搭載の「You should know」（`/plugin enable cc-plugin-you-should-know@builtin`で有効化、既定は無効）は、長時間タスクの裏でサブエージェントが見張り、Claudeやユーザーが見落としそうな点をプロンプト上部に通知する。
  - **なぜ注目されているか**: 公式ドキュメントが明記する通り、modは設定ファイル経由のhookやskillと違い「Claude Code本体のプロセス内で動くコード」であり、ユーザー権限で任意のファイル読み書き・プロセス起動・ネットワーク通信ができ、`ask`ルールやユーザー自身の`PreToolUse`hookがブロックした呼び出しさえ承認できてしまう強い権限を持つ（権限プロンプトの表示自体は書き換えられない）。`claude plugin validate`でインストール前にmodが何をするか一覧できる仕組みも同時に用意されており、便利さと引き換えに従来のskill/hookより一段信頼が必要な領域が増えたことを意味する。
  - **使いどころ**: skill/hook/routineを自作する関心が強いなら、まず「You should know」を自分のセッションで有効化し、長時間タスク中に何を拾ってくれるか試す価値がある。自作のmod開発はClaudeに「こういうmodが欲しい」と頼むだけでも書いてくれるとされているため、YouTube企画の「自作ツールで画面を拡張する」ネタにも向く。ただし他人が配布するmodは`claude plugin validate`で中身を確認してからインストールする運用を、経験の浅いメンバーにも周知しておくとよい。

- **[公式][実務] Claude Code v2.1.287（10/1）— Bashコマンド経由で安全装置をすり抜ける抜け道を3件修正（`rm`の確認スキップ、MCPツール名`__proto__`での権限上限無効化、whole-tool許可ルールでの保護ファイル書き込み）** — https://github.com/anthropics/claude-code/releases/tag/v2.1.287
  - **何が起きたか**: リリースノートに次の3件が明記された。(1)「`rm -rf /`等の常時確認対象コマンドが、同じコマンド内で`~`やワイルドカードパスへの出力リダイレクトを伴うと、常時確認の安全装置が外れてしまう」不具合を修正。(2)「組織が設定したツールごとの権限上限が、`__proto__`という名前のMCPツールに対しては無言で無効化されてしまう」不具合を修正。(3)「`Bash`ツール全体を許可するルールや許可側のhookがある場合、Claude Code本体のファイル編集ツールが書き込みを拒否する保護対象ファイル（Anthropicのプロファイルストアやホストの認証情報ファイル）にも、Bash経由なら書き込めてしまっていた」挙動を、以後は実行せず確認を求めるように変更。
  - **なぜ注目されているか**: 3件とも「個別には安全に見える許可設定（Bash全体の許可、MCPツールの権限上限、ファイル保護機構）が、Bashコマンドの組み立て方や命名次第で組み合わさって無効化される」という同系統の抜け穴で、同じリリースでまとめて塞がれた。特に(2)の`__proto__`はJavaScriptのプロトタイプ汚染でよく悪用される特殊な名前で、権限設定を実装するコード側の実装ミスに起因していたと読み取れる。
  - **使いどころ**: auto modeや`Bash(*)`のようなwhole-tool許可ルールで無人routineを組んでいるなら、v2.1.287への更新を優先する価値がある。経験の浅いメンバーのPRレビュー観点としても、「個別のルールは安全でも組み合わせで抜け道が生まれていないか」という視点は、CDK/IAMのポリシー設計レビューにもそのまま応用できる考え方。
