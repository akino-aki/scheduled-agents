- **[公式][企画] Claude Code v2.1.282 — compaction時の要約リクエストが「拒否（refusal）」されて丸ごと止まる不具合を修正、フォールバックモデルへの自動リトライに** — https://github.com/anthropics/claude-code/releases/tag/v2.1.282
  - **何が起きたか**: v2.1.282のリリースノートに「Fixed compaction failing when the summarization request is refused; it now retries on a fallback model」と明記された。会話の要約生成がAnthropicの安全性判定で拒否された場合、これまでは丸ごと失敗していたが、フォールバックモデルでの再試行に変わった。
  - **なぜ注目されているか**: Anthropicの拒否レスポンスはエラーではなくHTTP 200・`stop_reason: "refusal"`として返るため、通常のプロバイダーエラー扱いのフォールバック機構が発火せず、セッションがコンテキスト上限に張り付いたまま動かなくなるという構造的な問題が、同種のAnthropic API利用製品のissue（openclaw/openclaw #134127）で具体的に指摘されている。会話内容が安全性カテゴリに触れると、要約それ自体が拒否されうるという話。
  - **使いどころ**: このダイジェストのような無人スケジュールroutineや長時間`/goal`セッションでcompactionに依存しているなら、これまで無言で詰まっていた原因の一つが解消された可能性がある。バージョンを上げるだけで効くので更新しておく価値がある。

- **[実務] issue #96822 — acceptEditsモードで「ファイル編集の自動承認」と「よくあるコマンドの自動実行」が1つの確認にまとめられてしまう回帰報告（9/24, 未修正）** — https://github.com/anthropics/claude-code/issues/96822
  - **何が起きたか**: v2.1.281時点で、以前（v2.1.220）は別々だった「Accept edits」と「Execute common commands」の許可が1つのプロンプトに統合され、ファイル編集だけ自動承認したくてもコマンド実行の許可までまとめて渡さざるを得なくなったと報告されている。報告者は「開発速度が実質死んだ」と述べている。
  - **なぜ注目されているか**: 「ファイルの内容を変える」ことと「任意のコマンドを実行する」ことは安全性のレベルが全く異なるという原則的な指摘で、`area:permissions`・`bug`ラベルがついているが本稿執筆時点でメンテナー応答は無い。
  - **使いどころ**: 個人開発でacceptEditsモードを使っているなら、コマンド実行まで一括承認されていないか一度確認する価値がある。経験の浅いメンバーに「編集だけ自動承認、コマンドは都度確認」という運用ルールを教えているなら、現バージョンではその境界が実質無くなっている点に注意し、レビュー観点に「AIのコマンド実行が編集の確認に紛れていないか」を一時的に加えるとよい。

- **[実務] AWS公式`aws-core`プラグインに`amazon-eventbridge-event-bus`スキルが新規追加（9/24, PR #334）— クロスアカウントのイベント共有・リトライ/DLQ・リプレイまでカバー** — https://github.com/aws/agent-toolkit-for-aws/pull/334
  - **何が起きたか**: publish／subscriber filtering／target routing／順序保証・保持・リプレイ／リトライとdead-letter queue／クロスアカウントのイベント共有／監視までをカバーする新スキルが追加された。`aws-serverless`スキルからこの新スキルへのルーティングポインタも整備され、「classicなEventBridgeトピックは`aws-serverless`のまま」という除外リストも明記されている。
  - **なぜ注目されているか**: 9/21の`aws-well-architected-review`・9/23の`aws-fault-injection-service`（いずれも既報）に続き、`aws-core`プラグインが個別サービス単位のスキルを急速に拡充している流れの一つ。今回はクロスアカウントのイベント共有ガバナンスに触れている点が、単一アカウント前提の一般的なEventBridge解説記事には出てこない実務的な観点。
  - **使いどころ**: マルチアカウントのECS環境でイベント駆動連携（注文完了などのイベントを起点にECS taskをキックする等）を組んでいるなら、`aws-core`導入後にこのスキルでルーティング設計やDLQ設定のレビューをかけると、経験の浅いメンバー向けPRレビューチェックリスト作りの材料になる。

- **[実務][企画] issue #96859 — workspace trust dialogの「権限を適用せず続行」選択肢が回帰で消失、新規フォルダを開くと「全許可ルールを一括信頼」か「開かない」の二択に（9/24報告, 未修正）** — https://github.com/anthropics/claude-code/issues/96859
  - **何が起きたか**: v2.1.234では「信頼する／権限を適用せず続行／終了」の3択だったtrust dialogが、v2.1.278/280/282では「信頼する／終了」の2択に減っていると報告されている。表示の省略ではなく、許可ルールが3件だけの最小再現でも同様の挙動と確認済み。
  - **なぜ注目されているか**: 消えた選択肢は「フォルダの`permissions.allow`ルールを事前に適用せずまず開いて内容を確認する」という段階的な信頼のための分岐だった。これが無いと、新しいリポジトリや他人の`.claude/settings.json`を含むフォルダを開く際、内容を精査する前に全許可ルールをそのまま受け入れるか、フォルダを開かないかの二択を強制される。
  - **使いどころ**: 経験の浅いメンバーに未知のリポジトリでClaude Codeを使わせる場面があるなら、直るまでは「初めて開くフォルダの`.claude/settings.json`を先にレビューしてから信頼する」という手順を人間側の運用ルールとして明示しておくとよい。個人開発のクイズアプリのように自分だけが触るリポジトリなら今すぐの影響は無い。
