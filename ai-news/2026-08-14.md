- **[公式][実務] Claude Code v2.1.229 — `/commit-push-pr` が `--force`/`--amend`/`--no-verify` 等の危険フラグを自動承認しなくなった** — https://github.com/anthropics/claude-code/releases/tag/v2.1.229
  - **何が起きたか**: 8/12リリースのv2.1.229で、`/commit-push-pr`コマンドが生成するgit/ghコマンドのうち、`--force`・`--amend`・`--no-verify`などの危険フラグを含むものが自動承認の対象から外れ、明示的な確認が必要になった。
  - **なぜ注目されているか**: これまでこのコマンド経由の危険操作は他の通常のgit操作と同列に自動承認されており、強制pushや検証スキップが確認なしで通ってしまう余地があった。8/14からAuto modeがPro/Max/Teamの新規セッションで既定化される（8/9付ダイジェストで既報）タイミングの直前に、安全網の穴を塞ぐ形で入った変更。
  - **使いどころ**: 経験の浅いメンバーが8/14以降Auto modeのまま作業すると確認なし操作が増える中、少なくとも`/commit-push-pr`経由の強制push・検証スキップだけは今回の変更で確認が挟まるようになった。ただし直接`git push --force`等をBashで叩かせている場合は対象外なので、レビュー前にチームの運用がこのコマンド経由かどうか確認しておくとよい。

- **[公式][実務] Claude Code v2.1.229 — Bedrock/Vertex利用時、長考中の無応答ハングをSSEキープアライブで解消** — https://github.com/anthropics/claude-code/releases/tag/v2.1.229
  - **何が起きたか**: 8/12リリースのv2.1.229で、gatewayのストリーミング応答に長考中のSSEキープアライブpingが追加され、Vertex/Bedrock経由利用時にアイドルタイムアウトで接続が切れる問題が解消された。
  - **なぜ注目されているか**: 6/1報告のissue #64556など、Bedrock経由でクロスリージョン推論を使うと100秒以上無応答のままセッションがハングし、CloudWatch側にはエラーが一切出ない（Ctrl+Cで復帰はできる）という原因の切り分けにくい不具合が続いていた。重い使用で1〜3日に1回程度、大きめのコンテキストでの長時間セッションほど発生しやすいとされていた。
  - **使いどころ**: マルチアカウント環境で社内ゲートウェイ経由・Bedrock経由でClaude Codeを使っている場合、これまで「たまに応答が固まって理由不明」だった事象の一部はこの更新で解消される可能性がある。引き続き発生する場合は別原因を疑ってよい。

- **[公式] Claude Code v2.1.231 — MCP OAuthのリダイレクトURI不一致で認証失敗するバグを修正（Slack等）** — https://github.com/anthropics/claude-code/releases/tag/v2.1.231
  - **何が起きたか**: 8/13リリースのv2.1.231で、Slackのように事前登録済みのOAuthクライアントを使うMCPサーバーに対して、Claude Code側が送るリダイレクトURIが登録内容と一致せずOAuth認証が失敗する不具合が修正された。
  - **なぜ注目されているか**: Slack MCPプラグインでは3/23報告のissue #37714以降、`http://localhost:3118/oauth/callback`がSlack側の許可リストに存在せず認証が即座に拒否される不具合が長期間報告され続けていた。今回はSlackに限らず「事前登録済みOAuthクライアント」を使う構成全般への修正として入った。
  - **使いどころ**: Slack等のMCP連携でOAuth認証が通らず諦めていた場合、v2.1.231へのアップデートで解消している可能性がある。今すぐ使っていないなら急ぎではないが、今後YouTube企画でSlack通知連携などを試す際に選択肢に入れやすくなった。
