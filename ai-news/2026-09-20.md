- **[公式][企画] Claude Code Projects が刷新 — 1つの会話でClaudeが並列スレッドを調整、共有メモリとPRベースのマージに対応（Pro/Max限定ベータ、9/17〜）** — https://code.claude.com/docs/en/claude-projects
  - **何が起きたか**: 9/17に「Projects」が全面刷新された。1つの継続会話（コーディネーター）がタスクごとに複数のクラウドセッション（スレッド）を並列起動し、各スレッドは自分のブランチで作業してPRを開き、進捗はOverviewペインに集約される。Pro/Maxプランのベータで、クラウドセッション利用済みのアカウントから順次展開中（Team/Enterprise・CLI・ローカルセッションは対象外）。
  - **なぜ注目されているか**: 従来は複数セッションを走らせても「どれに何を頼んだか」「どれが終わったか」を人間が自分で追う必要があった。今回はClaudeがタスクの振り分け・進捗管理・スレッド間の申し送り（プロジェクトメモリ）まで担い、1日200スレッドまでの上限はあるものの、外出中にタスクを積んでおいて後で結果だけ確認する、という使い方が公式にサポートされた形。
  - **使いどころ**: 個人開発のクイズアプリで「出題登録→レビュー→公開」を複数スレッドに分担させる自動化の土台になりうる。ただしPro/Maxプランでは通常セッションより利用枠の消費が速い点は要注意。YouTube企画では「離席中にAIが並列でPRを作ってくる」画が撮れるので、デモ素材としても使える。

- **[実務] aws-core プラグインの aws-cloudformation スキル更新（9/18, PR #318）— CloudFormationテンプレートの検証手順をツール別ガイドに再構成、cfn-lintに加えcloudformation-validate/cfn-guardの使い分けを明記** — https://github.com/aws/agent-toolkit-for-aws/pull/318
  - **何が起きたか**: AWS公式のClaude Code向けプラグイン`aws-core`内`aws-cloudformation`スキルが、従来cfn-lint単体を前提にしていた検証手順を、ツールごとの専用ガイド（cfn-lintまたはcloudformation-validate／cfn-guardによるセキュリティチェック／デプロイ前のアカウント認識検証）に分割した。
  - **なぜ注目されているか**: このスキル自体は「plain CloudFormation」向けで、SKILL.mdには「CDKの場合はCDK向けスキルを使うこと」と明記されており、CDKが合成したテンプレートは対象外と位置づけられている。ただしcfn-lintやcfn-guardはCDKが吐き出すJSONテンプレートに対しても単体のCLIとして動くため、検証ツールの使い分け情報自体はCDK運用にも転用できる。
  - **使いどころ**: このスキルをCDKプロジェクトのレビューに直接使わせることはできないが、`cdk synth`の結果をcfn-lint/cfn-guardでチェックするCI手順を整備する際の参考になる。経験の浅いメンバー向けレビューチェックリストに「セキュリティ観点はcfn-guardで機械的に落とす」項目を足す材料程度で、今すぐ導入必須というほどではない。

- **[公式] Claude Code v2.1.278（9/19）— Auto modeの安全性チェックをサーバー側で実行しトークン課金しない方式がデフォルト化、対象はEnterprise/Claude API/Bedrock/Vertex/Foundry** — https://github.com/anthropics/claude-code/releases/tag/v2.1.278
  - **何が起きたか**: v2.1.278で、Auto modeが各ツール呼び出し前に行う安全性チェック（分類器）を、Enterprise/Claude API契約およびBedrock/Vertex/Foundry/ゲートウェイ経由の利用ではサーバー側で実行し、そのぶんのトークン課金をしない方式がデフォルトになった。ゲートウェイがヘッダーや`safeguards`フィールドを削ってしまう環境では従来通りの課金方式にフォールバックし、セッション開始時に通知が出る。
  - **なぜ注目されているか**: これまでAuto modeの分類器チェックはEnterprise/API/Bedrock等の契約では通常のトークン使用としてそのまま課金されていた。公式ドキュメントには「Pro/Max/Teamプランではこの通知は一切出ない」と明記されており、個人向けプランはもともとこの課金対象になっていなかったことが今回の変更で公式に確認できた形。
  - **使いどころ**: Pro/Max/Teamプランで使っているなら影響はない。マルチアカウントAWS環境でBedrock経由のClaude Codeを検証中、またはClaude API契約でCI/CDに組み込んでいるなら、`/status`の「Auto mode server」欄が`Enabled`になっているか一度確認する価値がある。
