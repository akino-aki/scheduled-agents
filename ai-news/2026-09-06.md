- **[公式][実務] Claude Code v2.1.261 — `--append-subagent-system-prompt-file`追加、コマンドライン経由では長すぎるサブエージェント向けシステムプロンプトをファイルから読み込み可能に（非対話`-p`モード限定）** — https://github.com/anthropics/claude-code/releases/tag/v2.1.261
  - **何が起きたか**: v2.1.261で`--append-subagent-system-prompt-file`が追加された。既存の`--append-subagent-system-prompt`と同じくサブエージェントのシステムプロンプトに文章を追加するが、コマンドライン引数ではなくファイルから読み込める。両者は併用不可で、非対話モード（`-p`）でのみ有効。
  - **なぜ注目されているか**: メインセッション向けの汎用`--append-system-prompt-file`相当の要望（2025年8月報告のissue #6153、`$(cat ROLE.md)`のようなシェルのコマンド置換を使わずファイルパスを直接指定したいという内容）は「Closed as not planned」のまま終わっていた。今回はそれとは別に、サブエージェント向けに限定した形で同種の機能が実装され、長いルール文書をコマンドライン経由で渡す際の引数長制限を回避できるようになった。
  - **使いどころ**: 自作のCDK/ECSレビュー用サブエージェントに長めのレビュー観点（ROLE.mdのようなファイル）を渡し、`-p`でバッチ的に回す運用をしているなら、コマンドライン引数を経由せずファイルで直接渡せるようになる。ただし対話モードの通常セッションでは使えない点に注意。

- **[公式][実務] Claude Code v2.1.261 — `/status`と`claude doctor`に「Organization policy」の行を追加、組織ポリシーが読み込めなかった理由（プロキシがエンドポイントを通していない等）を表示** — https://github.com/anthropics/claude-code/releases/tag/v2.1.261
  - **何が起きたか**: v2.1.261で`/status`と`claude doctor`に「Organization policy」の行が追加され、組織のmanaged settingsのポリシーが読み込めなかった場合、その理由（例えばプロキシがエンドポイントを素通りさせていない、など）が表示されるようになった。
  - **なぜ注目されているか**: 同じv2.1.261には他にも「Bedrockセットアップウィザードが、AWSや認証情報ヘルパーが応答しないまま無限にハングする問題」や「Remote Controlの受信イベントストリームがネイティブWindowsのTLS検査プロキシ背後で失敗する問題」など、TLS検査プロキシ（企業のセキュリティ製品がHTTPS通信を復号・検査する構成）絡みの不具合修正が同時に複数含まれている。原因が分からないまま機能が静かに動かない、という企業ネットワーク特有の問題への対処がこのリリースでまとめて進んだ形になる。
  - **使いどころ**: 会社のTLS検査プロキシ配下でClaude Codeを使っている、あるいは組織のmanaged settingsを導入・検討しているなら、`/status`の表示だけで「プロキシ側の設定漏れ」に当たりを付けやすくなる。個人開発環境では使う場面がないので今すぐは不要。

- **[公式][企画] Claude Code v2.1.261 — プロンプト入力のワード編集キー（Ctrl+W等）がBash準拠の挙動に統一、8月に追加されたばかりの`keybindingFlavor`設定は効果を持たなくなった** — https://github.com/anthropics/claude-code/releases/tag/v2.1.261
  - **何が起きたか**: v2.1.261で、プロンプト入力欄のワード編集キーがBashと同じ挙動に統一された。Ctrl+Wは直前の空白まで削除、Alt+FとAlt+Dは単語の終わりで止まる・削除、句読点も単語の区切りとして扱われる。8/21リリースのv2.1.239で追加されたばかりの設定`keybindingFlavor`（"readline"/"classic"の切り替え）は、以後どちらを指定しても効果を持たなくなった。
  - **なぜ注目されているか**: 「Ctrl+Wが効かない」という報告（2026年3月報告のissue #38807、Windows環境でのリグレッションとして）は以前からあり、v2.1.239でオプトイン設定`keybindingFlavor: "readline"`としていったん解決されていた。今回はそのオプトイン設定自体を廃止し、全ユーザーに強制適用する形に変わった。1か月足らずで「選べる設定」から「唯一の挙動」へと切り替わった格好になる。
  - **使いどころ**: Bashに慣れていれば違和感なく馴染むはずだが、`keybindingFlavor`を"classic"のままにして従来の挙動に依存していた人は、意図せずCtrl+Wなどの動きが変わっている。自分の`~/.claude/keybindings.json`をカスタマイズしているなら、アップデート後に一度動作を確認しておくとよい。YouTube収録中に「Ctrl+Wで単語単位削除」を実演するような小ネタにも使える。
