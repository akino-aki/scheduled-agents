- **[公式][実務] Claude Code v2.1.239 — プロキシ配下のBedrockストリーミングで、気づかぬまま課金が倍になっていた不具合を修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.239
  - **何が起きたか**: 8/21リリースのv2.1.239で、レスポンスのContent-Typeヘッダーを除去するプロキシ配下でBedrock経由のストリーミングを使うと、Claude Codeが気づかず各ターンを非ストリーミングとして再実行し、API呼び出しの課金が実質2倍になっていた不具合が修正された。
  - **なぜ注目されているか**: リリースノート自身が「サイレントに課金が倍になっていた（silently doubled billed API calls）」と明記しており、エラー表示も一切ないまま料金だけが積み上がる、気づきようのない種類の不具合だった。社内ゲートウェイやプロキシ経由でBedrockを利用する構成ほど起きやすい。
  - **使いどころ**: マルチアカウント環境で社内プロキシ経由でBedrockのClaude Codeを使っているなら、v2.1.239へのアップデートを優先。ここ最近の利用料が想定より高いと感じたことがあれば、原因の一つとして疑える。

- **[公式][実務][企画] Claude Code v2.1.239 — `/goal`のチェックイン間隔が30分固定から段階的に延びる方式に変更** — https://github.com/anthropics/claude-code/releases/tag/v2.1.239
  - **何が起きたか**: 同v2.1.239で、`/goal`がバックグラウンド作業の完了を待つ際のチェックイン間隔が「30分ごとに繰り返し」から「30分→1時間→以降2時間ごと」と段階的に間隔を広げる方式に変わった。
  - **なぜ注目されているか**: 8/17のv2.1.234で「バックグラウンドタスクを30分以上待ったら自動で様子を見に行く」機能が入ったばかりだった（8/18付ダイジェストで既報）。今回はその追跡頻度自体を見直し、30分おきに延々とチェックインし続けてコンテキストや通知を消費する状態を緩和した形。
  - **使いどころ**: このscheduled-agentsのようにroutineや`/loop`で`/goal`を使い長時間の自律作業をさせているなら、無駄なチェックインが減り、より長時間放置する運用に向いた挙動になった。

- **[公式][企画] Claude Code v2.1.239 — `ListAgents`が自分のteammateを一覧表示するように修正（従来は表示漏れ）** — https://github.com/anthropics/claude-code/releases/tag/v2.1.239
  - **何が起きたか**: 同v2.1.239で、`ListAgents`と`/list-agents`が自分のteammate（チームメイト）も一覧表示するようになった。従来はサブエージェントや他セッションのみが表示され、実際に話しかけられるteammateが一覧に出てこなかった。
  - **なぜ注目されているか**: セッション間メッセージングは8月に入って`@`メンション（8/13）や`notify_when_idle`（8/19）など段階的に拡張されてきた機能（8/15・8/20付ダイジェストで既報）。その土台となる`ListAgents`自体に「本来話しかけられる相手が一覧に出ない」という基本的な可視性の不具合が残っていた、という話。
  - **使いどころ**: 複数セッション・複数worktreeを連携させる設計をしているなら、これまで`ListAgents`で見えなかったteammateが見えるようになり、`@`メンションで直接呼びかけやすくなる。「AI同士が会話しながら開発する」YouTube企画を試すなら、まずこの一覧表示が正しく機能しているか確認するとよい。

- **[実務] Claude Code v2.1.239 — 組織の支出上限超過・クレジット切れでは再試行を待たず即座に失敗するように** — https://github.com/anthropics/claude-code/releases/tag/v2.1.239
  - **何が起きたか**: 同v2.1.239で、接続断時に自動で再試行し続ける`CLAUDE_CODE_RETRY_WATCHDOG`（persistent retry mode）が、組織の支出上限超過やクレジット枯渇のエラーに対しては、リセットされるまで無期限に待ち続けるのをやめ、即座に失敗するようになった。
  - **なぜ注目されているか**: リリースノートによれば、従来はこの watchdog がこうしたエラーもネットワーク瞬断と同列に扱い、リセットされるまで待ち続けてしまっていた。無人運用中に「実は上限に達して何もしていなかった」ことに気づけない状態が起きうる仕様だった。
  - **使いどころ**: routineやWorkflowを長時間無人で回している場合、組織のクレジット切れに気づかずセッションが待機し続ける事故が減る。個人開発のクイズアプリの自動化をバッチ的に無人で回しているなら、上限超過時に早く気づけるようになる点は覚えておくとよい。
