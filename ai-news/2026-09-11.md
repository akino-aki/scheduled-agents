- **[公式][実務] Claude Code v2.1.268 — Bash `Read()`/`Edit()` deny ruleが`env -C`や`eval`経由のコマンドをすり抜ける不具合を修正、月初から続く抜け穴塞ぎの第3弾** — https://github.com/anthropics/claude-code/releases/tag/v2.1.268
  - **何が起きたか**: v2.1.268で、`env -C DIR cat FILE`や`eval`のようにコマンドをラップする経路が、Read/Edit deny ruleをすり抜けて拒否対象ファイルを読めてしまっていた不具合が修正された。
  - **なぜ注目されているか**: このダイジェストでは9/4付でオプション引数値や`git diff`・コマンド連結のすり抜け（v2.1.259）、9/5付でその修正自体が`npm run build`を誤ブロックした副作用（v2.1.260）を報じてきた。今回は同じBash deny ruleの抜け穴塞ぎの3件目にあたり、月をまたいでもまだ別の迂回経路が見つかり続けている。
  - **使いどころ**: `.claude/settings.json`で`.env`などをdeny ruleで守っているなら、これまで`env -C`や`eval`を使ったコマンドで気づかず読めていた可能性がある。経験の浅いメンバー向けレビューチェックリストの「Bash許可・拒否ルールのすり抜け確認」項目を、今回のパターンも含めて更新しておくとよい。

- **[公式][企画][実務] Claude Code v2.1.268 — WebFetchが応答を返さず無期限にハングする不具合を修正、300秒（`CLAUDE_CODE_WEBFETCH_DEADLINE_MS`で変更可）で必ずタイムアウトするように** — https://github.com/anthropics/claude-code/releases/tag/v2.1.268
  - **何が起きたか**: v2.1.268で、WebFetchが応答を受け取れないまま無期限にハングする不具合が修正され、既定300秒でタイムアウトしエラーを返すようになった。上限は環境変数`CLAUDE_CODE_WEBFETCH_DEADLINE_MS`で調整できる。
  - **なぜ注目されているか**: 2025年11月報告のissue #12113では、あるサイトへのWebFetchが応答済みにもかかわらず3時間ハングし続け、手動キャンセルするまで約20〜30ドル分の追加課金（本来11ドル程度のセッションが31ドルに）が発生したと報告されており、当時「重複issue」扱いになるほど既知の問題だった。無応答のまま課金だけ続くタイムアウト不在の問題が、ようやく上限付きで解消された形になる。
  - **使いどころ**: このダイジェストのように自作routineやskillでWebFetchを多用する自動化を組んでいるなら、詰まったまま課金され続ける事故のリスクが下がる。長い解析ページなど300秒で足りない用途があれば、`CLAUDE_CODE_WEBFETCH_DEADLINE_MS`を伸ばして使うとよい。

- **[公式][実務] Claude Code v2.1.267 — 組織設定`maxEffortLevel`追加、Bedrock/Vertex/Foundry含む全プロバイダでeffortレベルの上限をチームに強制可能に（ユーザーはそれより下は選べる）** — https://github.com/anthropics/claude-code/releases/tag/v2.1.267
  - **何が起きたか**: v2.1.267で`maxEffortLevel`設定（トップレベルまたは`modelSettings`配下でモデルごと）が追加された。Bedrock/Vertex/Foundryを含む全プロバイダでeffortレベルの上限を強制でき、`--effort`や`/effort`で上限より高い値を指定しても上限で頭打ちになる。ユーザーは上限以下のレベルは自由に選べる。
  - **なぜ注目されているか**: 同種の要望（issue #55598、共有ホストやCIランナーでの管理者向けユースケース）は、`CLAUDE_CODE_MAX_EFFORT_LEVEL`のような環境変数による上限強制を求めて2025年に一度「Closed as not planned」となっていた。既存の`CLAUDE_CODE_EFFORT_LEVEL`は「ユーザーが変更できない固定値」にしかならず、自律的なマルチエージェントワークフローが再起動を繰り返すたびに共有クォータを食いつぶす、という問題が指摘されていた。今回は別の形（管理設定＋上限のみ強制）でこの課題に答えている。
  - **使いどころ**: 経験の浅いメンバーがxhighのようなeffortを乱用してAPIコストを膨らませるのを防ぎたいなら、組織のmanaged settingsで`maxEffortLevel`を設定しておける。個人開発では今すぐ使う場面はないが、チーム導入時の選択肢として覚えておく価値がある。

- **[公式][実務] Claude Code v2.1.267 — `/model`でのモデル切り替えがツール定義を毎回全送信しプロンプトキャッシュを無効化していた不具合を修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.267
  - **何が起きたか**: v2.1.267で、`/model`でモデルを切り替えるとツール定義が毎回すべて再送信されキャッシュミスになっていた不具合が修正された。コミット/PR用の帰属文言（attribution text）も、モデル変更時に更新される会話内ノートとして扱われるよう変更された。
  - **なぜ注目されているか**: 9/9付ダイジェストで報じた「SendMessageでのサブエージェント/teammate再開が毎回キャッシュミスしていた不具合（issue #44724、再開のたびに約10倍のコスト）」と同じ、プロンプトキャッシュ関連の不具合修正がv2.1.265→v2.1.267と続けて入っている。今回は`/model`での切り替えが対象で、キャッシュ崩壊のパターンが複数箇所に存在していたことがうかがえる。
  - **使いどころ**: タスクの内容によって`/model`でモデルを切り替える運用をしているなら、これまで切り替えのたびに割高なキャッシュミス課金が発生していた可能性がある。バージョンを上げるだけで効く改善で、対応は不要。
