- **[公式][企画] Claude Code v2.1.251 — Remote Controlに、フォアグラウンドのサブエージェントのツール呼び出し・結果をライブストリーミング表示** — https://github.com/anthropics/claude-code/releases/tag/v2.1.251
  - **何が起きたか**: 8/28リリースのv2.1.251で、フォアグラウンドで動くサブエージェントのツール呼び出しと結果が、Remote Control接続先（スマホのCodeタブなど）にリアルタイムでストリーミング表示されるようになった。バックグラウンドのサブエージェントは従来通りステータス表示のみ。
  - **なぜ注目されているか**: Remote Control自体は8/23付ダイジェストで既報の通りリサーチプレビューを終えたばかりで、直後のこのリリースで「マシンのデバイスカードから開ける」だけでなく「サブエージェントが今何をしているか」まで覗ける方向に機能が伸びている。これまでは親セッションの様子しか見えず、サブエージェントの動きはスマホ側からは追いにくかった。
  - **使いどころ**: `/loop`やWorkflowでCDK/ECSの調査をサブエージェントに任せて離席するとき、スマホから「今どのツールを叩いているか」まで見えるようになる。YouTube収録中に「スマホでサブエージェントの動きを覗く」デモがそのまま使える。

- **[公式][実務] Claude Code v2.1.251 — プラグインのコマンドパス・Workflowツールの`scriptPath`・Grep/Glob経由のシンボリックリンクで、パストラバーサル系の不具合を3件修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.251
  - **何が起きたか**: 同v2.1.251で、①マーケットプレイス側で宣言したプラグインコマンドのパスがプラグインディレクトリ外を指せてしまう問題、②Workflowツールが権限チェックより前に許可範囲外の`scriptPath`を読んでしまう（エラーメッセージにも引用してしまう）問題、③Grep/Globがシンボリックリンク経由で到達したファイルに`Read()`の拒否ルールを適用していなかった問題、の3件が修正された。
  - **なぜ注目されているか**: 8/29付ダイジェストで既報の「ファイルツールが権限確認後のシンボリックリンクすり替えに追従しない」修正と同じv2.1.251内の話で、いずれも「許可した範囲の外へ読み書きが漏れる」パストラバーサル系の穴という共通点がある。プラグインやWorkflowなど、外部由来の設定・スクリプトを扱う経路にこの種の穴が集中して残っていたことになる。
  - **使いどころ**: マルチアカウント環境でプラグインやWorkflowスクリプトを社内共有する運用をしているなら、直接手を入れる機能ではないが、バージョンを上げておくことが対策になる。経験の浅いメンバーのレビューで「パス・シンボリックリンクの扱い」を見るときの一般知識として頭に入れておくとよい。

- **[公式][実務][企画] Claude Code v2.1.247 — 組み込みskill `claude-api`に`/claude-api cost-optimize`を追加、API利用コストをプロファイルしてキャッシュ・トークン節約・バッチ処理・effortレベル・モデル選択の順に見直し提案** — https://github.com/anthropics/claude-code/releases/tag/v2.1.247
  - **何が起きたか**: 8/26リリースのv2.1.247で、`claude-api`スキルに`/claude-api cost-optimize`コマンドが追加された。既存プロジェクトのClaude API利用実態をプロファイルし、キャッシュ活用・トークン節約・バッチ処理・effortレベル・モデル選択という順にコスト削減の余地を洗い出し、それぞれの変更を個別に効果測定する。
  - **なぜ注目されているか**: `claude-api`スキルは8/19付ダイジェストで既報の通りコンテキストコストを200k超→約25kトークンに削減した機能で、8/24付ダイジェストでは`/claude-api upgrade`（SDK移行支援）が追加された経緯がある。今回はその延長で、自分のAPI利用プロジェクトのコスト自体を診断・改善する用途にスキルが広がった形。
  - **使いどころ**: 個人開発のクイズアプリで出題判定にAPIを直接呼ぶ実装をしているなら、`/claude-api cost-optimize`でキャッシュ設定やモデル選択に無駄が無いか棚卸しできる。プロジェクト自体がClaude Codeでの開発が中心でAPIを直接呼ぶ場面が少ないなら、今すぐは不要。

- **[公式][実務] Claude Code v2.1.251 — `CLAUDE_CODE_SUBAGENT_MODEL`が「全サブエージェントのモデルを問答無用で上書き」から「未指定時のデフォルトを設定」する挙動に変更** — https://github.com/anthropics/claude-code/releases/tag/v2.1.251
  - **何が起きたか**: 同v2.1.251で、環境変数`CLAUDE_CODE_SUBAGENT_MODEL`の挙動が変更された。リリースノートによれば、従来はこの変数がエージェント定義の`model:`フロントマターや起動時に個別指定したモデルも含めて全て上書きしていたが、変更後は「値を指定していないサブエージェントに使うデフォルト」となり、エージェント定義側の`model:`や個別指定のモデルが優先されるようになった。
  - **なぜ注目されているか**: 8/27付ダイジェストで既報の`modelPicker`（Bedrock/Vertex経由で複数モデルをラベル付けして使い分ける設定）のように、サブエージェントごとにモデルを使い分けたい構成が増えている中、環境変数1つで意図せず全サブエージェントのモデルが揃ってしまう挙動は、細かく使い分けたい設計と噛み合っていなかった。
  - **使いどころ**: Bedrock/Vertex経由で複数モデルを切り替えながらサブエージェントを多用しているなら、`CLAUDE_CODE_SUBAGENT_MODEL`をコスト上限用のデフォルトとして緩く設定しつつ、重要なサブエージェントだけ個別に`model:`を指定する、という運用がしやすくなる。ただし本記事執筆時点で公式ドキュメント（`model-config`）側の説明は旧挙動のままだったため、実際の挙動は手元での確認を推奨する。
