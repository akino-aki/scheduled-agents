- **[公式][企画] Claude Code に `/design` が追加 — CLIとDesktopでUIの編集可能なドラフト案を生成するリサーチプレビュー** — https://code.claude.com/docs/en/whats-new/2026-w34
  - **何が起きたか**: 8/17〜21のアップデートで、artifacts基盤の「Claude Design」のアートボード編集ワークフローをCLI/Desktop内に持ち込む`/design`スキルがリサーチプレビューとして追加された（v2.1.233以降、Pro/Max/Team/Enterprise対象）。`/design`にお題を渡すとClaudeが複数案を1枚のキャンバスに描き、URLが提示される。開いて気に入った案を選び「これを実装して」と伝えると、そのままClaude Codeが実装に入る。
  - **なぜ注目されているか**: 「Claude Design」自体は4月にブラウザ上の別ツール（Opus 4.7ベース）として登場し、6月にベータへ昇格した既存の機能。これまではデザイン案の作成（ブラウザのClaude Design）と実装（Claude Code）でツールを行き来する必要があったが、今回`/design`によって同じアートボック案生成ワークフローがCLI/Desktopの中に統合され、ツールを切り替えずに「案出し→選択→実装」まで完結できるようになった。
  - **使いどころ**: Next.jsクイズアプリの出題画面・結果画面のUI案を、実装前にClaude Code内でいくつか出させてから選んで実装させる、という使い方ができる。「AIにUI案を複数出させて選ぶ」過程はそのままYouTube企画の見せ場にもなる。まだリサーチプレビューなので、本番の細かいスタイル調整は結局手で詰める前提で見ておくとよい。

- **[公式][実務][企画] Remote Control がリサーチプレビューを終了 — スマホの Code タブに「デバイスカード」として自分のマシンが表示されるように** — https://code.claude.com/docs/en/whats-new/2026-w34
  - **何が起きたか**: 8/17〜21のアップデートで、`claude remote-control`を起動しているマシンがClaudeアプリのCodeタブ上部に「デバイスカード」として表示され、タップするとそのマシン上のディレクトリを選んでセッションを開始できるようになった。あわせてRemote Control自体がリサーチプレビューを終了。同時期のv2.1.238では、プロセスがクラッシュしたセッションを次のメッセージで再利用できるようにする修正、ブラウザ/Desktopからのメッセージが送信中に消える不具合の修正、サインイン更新の遅延で切断される問題への再試行対応など、Remote Control関連の信頼性修正がまとまって入っている。
  - **なぜ注目されているか**: Remote Controlはこのセッション（scheduled-agents）自体が動いている基盤でもあり、セッション間メッセージング（8/7のv2.1.224で追加、以降8/8・8/9・8/13・8/20・8/21付ダイジェストで既報の一連の拡張）とも接続している。今回はその土台部分が「プレビュー」の看板を下ろし、あわせて接続まわりの細かい不具合修正が一度に集中投入された形。
  - **使いどころ**: `/loop`やroutineでCDK/ECSの調べ物やビルドを長時間動かしているときに、離席中でもスマホのCodeタブからそのマシンのセッションを覗いたり指示を出したりできる。YouTube収録中に別マシンのセッションを操作するデモにもそのまま使える。

- **[公式][企画] Claude Code v2.1.239 — `/goal`のバックグラウンド待機チェックインが「30分ごと」から段階的に間隔を空ける方式に変更** — https://github.com/anthropics/claude-code/releases/tag/v2.1.239
  - **何が起きたか**: 8/21リリースのv2.1.239で、`/goal`がバックグラウンド作業の完了を待つ際のチェックイン間隔が、30分→1時間→以降2時間ごと、と段階的に空くよう変更された。以前（8/17のv2.1.234、8/18付ダイジェストで既報）は「30分待ったら様子を見に行く」という固定間隔だった。
  - **なぜ注目されているか**: v2.1.234の30分チェックインは、バックグラウンド処理の完了通知が反映されずセッションが無反応のまま止まる不具合（issue #40462など）への対策として入った経緯がある。今回はその対策自体を維持しつつ、待機が長引くセッションで30分ごとに律儀にチェックインし続けるとその分のやり取りやコストがかさむ、という新たな副作用を抑える調整。
  - **使いどころ**: `/goal`でCDK/ECSのデプロイ完了待ちなど長時間の自律作業をさせている場合、待機が長引くほど無駄なチェックインの頻度が下がりコストを抑えやすくなる。このダイジェスト自身のroutineでも「様子見の間隔をどう決めるか」は同じ悩みどころで、自作するskill/hook/routineの間隔設計を考えるときの参考になる。
