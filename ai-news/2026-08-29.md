# 2026-08-29

> **収集環境について**: 本日も `zenn.dev` `qiita.com` などへのアクセスが egress プロキシにより `EGRESS_BLOCKED` で、日本語の実践記事・活用事例の原文確認ができませんでした（引き続き継続中）。今回も原文を直接読めた公式ソース（GitHub `anthropics/claude-code` releases・CHANGELOG.md、関連Issue）から、背景まで裏取りできた4件を掲載します。すべて8/28リリースのv2.1.251由来です。

- **[公式][実務][企画] Claude Code v2.1.251 — `PreModelSwitch`/`PostModelSwitch`フック追加、モデル切り替えのブロック・確認・注釈付けが可能に** — https://github.com/anthropics/claude-code/releases/tag/v2.1.251
  - **何が起きたか**: 8/28リリースのv2.1.251で、モデル切り替えが発生した際に発火する`PreModelSwitch`/`PostModelSwitch`フックイベントが追加された。切り替えのブロック・確認・メタ情報の付与ができる。
  - **なぜ注目されているか**: モデル切り替えをフックで制御したいという要望は3月のissue #31342（プロンプトの複雑さに応じてモデルを自動ルーティングしたいというコスト削減目的の要望、duplicate close済み）などから出ていた。8/28付ダイジェストで既報のサブエージェント側のモデル404フォールバックのように、Claude Code自体が裏でモデルを切り替える場面が増えており、その切り替え自体を可視化・制御する土台が今回整った形。
  - **使いどころ**: `modelPicker`（8/27既報）で複数モデルを切り替える運用や、Bedrock経由でフォールバックが起きる構成なら、`PostModelSwitch`フックでログ記録や通知を仕込み「いつ・なぜモデルが変わったか」を追えるようにできる。自作hookのネタとしてそのままYouTube企画にも使える。

- **[公式][実務] Claude Code v2.1.251 — ファイルツール（Read/Write/Edit）が権限確認後のシンボリックリンクすり替えに追従しないよう修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.251
  - **何が起きたか**: 同v2.1.251で、ファイル系ツールが権限確認を終えた後にパスをシンボリックリンクへすり替えられても追従しないよう修正された。
  - **なぜ注目されているか**: 「権限チェックと実際のファイル操作の間にシンボリックリンクをすり替える」TOCTOU型の攻撃は、4月に報告されたCVE-2026-39861（サンドボックス内で作成したシンボリックリンクを使いワークスペース外への書き込みを許してしまう脆弱性、v2.1.64で修正済み）と同じ攻撃パターン。今回はサンドボックスに限らず、ファイルツールの権限チェック処理そのものに同種の穴が残っていたことになる。
  - **使いどころ**: 直接触る機能ではないが、マルチアカウント環境でリポジトリ操作をClaude Codeに任せる際の安全性の土台が一段固くなったと理解しておけばよい。バージョンを上げておく以外に特別な対応は不要。

- **[公式][実務] Claude Code v2.1.251 — `/cost`にセッション単位のプロンプトキャッシュ統計（ヒット率・ミス数・warm/cold）を追加** — https://github.com/anthropics/claude-code/releases/tag/v2.1.251
  - **何が起きたか**: 同v2.1.251で、`/cost`にセッション単位のプロンプトキャッシュ統計（ヒット率、ミス数、再キャッシュされたトークン数、warm/cold内訳）が追加された。
  - **なぜ注目されているか**: 8/26付ダイジェストで既報の`promptCacheTtl`/`subagentPromptCacheTtl`（既定5分のキャッシュ保持を1時間に延ばせる設定）は、設定した効果を確認する手段がこれまでなかった。今回はその効果を`/cost`で直接確認できるようになった。
  - **使いどころ**: 社内プロキシ経由でBedrockのClaude Codeを使いCDK/ECSの長時間調査をしているなら、`promptCacheTtl: "1h"`設定後に`/cost`でヒット率を見て、実際にキャッシュが効いているか、逆に短時間作業が多く1時間キャッシュがコスト増になっていないかを確認できる。

- **[公式][実務] Claude Code v2.1.251 — SDK MCPサーバーのハンドシェイク応答取りこぼしによる無期限ハングを修正、70秒でタイムアウト** — https://github.com/anthropics/claude-code/releases/tag/v2.1.251
  - **何が起きたか**: 同v2.1.251で、SDK・クラウドセッションでSDK MCPサーバーのハンドシェイク応答を取りこぼした際に無期限にハングしていた不具合が修正され、70秒でタイムアウトして該当サーバーのみ失敗扱いになるよう変更された。
  - **なぜ注目されているか**: MCPサーバーの初期化ハングは以前から繰り返し報告されてきた問題で、issue #15945は「16時間以上ハングし自動復旧できない」重大バグとして、issue #35287は「stdioのMCPサーバー起動失敗時にタイムアウトも死活監視もなく無期限に待ち続ける」と報告していた。今回はそのうちSDK MCPサーバー・SDK/クラウドセッションに限った範囲で、ようやくタイムアウトが入った形。
  - **使いどころ**: 自作のClaude Agent SDKベースのツールやMCPサーバーを組み込んで自動化しているなら、応答が返らないMCPサーバーのせいでセッション全体が固まる事故が減る。ただしCLI通常セッションでのMCP起動ハング自体は別issueとしてまだ残っている点は覚えておくとよい。
