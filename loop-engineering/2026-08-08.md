# 2026-08-08

- **[実装][停止条件] Claude Code v2.1.224 — セッション間メッセージング(SendMessage/ListAgents)とサブエージェント200体上限の撤廃** — https://github.com/anthropics/claude-code/releases/tag/v2.1.224
  - **何が起きたか**: 別マシンをまたぐものも含め、複数のClaude Codeセッション同士が`SendMessage`/`ListAgents`で直接メッセージをやり取り可能に。同時にセッションあたり200体だったサブエージェント生成上限を撤廃（同時実行数・深さの制限は継続）。公式ドキュメントには「同一送信者からの反復メッセージはレート制限、受信待ちキューは1セッション最大50件」という組み込みの暴走防止設計が明記されている。（2026-08-07公開）
  - **なぜ注目されているか**: 従来、独立して動く複数セッションが「今分かったことだけ」を軽く伝え合う手段がなく、並行するworktreeセッションが互いの変更を知らずに衝突する不満があった。サブエージェント上限撤廃も、大規模ループ運用者が1セッション200体の壁にぶつかっていたことへの直接対応。
  - **自分の設計への示唆**: worktree並列運用で「セッションAのスキーマ変更をセッションBに通知」のような横連携を組めるようになる。ただし2セッション間でメッセージを送り合わせる設計にするなら、公式のスロットリング任せにせず自前の停止条件も持つべき。出題生成→検証が1セッション内で完結する今の設計なら不要、複数エージェントに分業させ始めたら見直す。

- **[実践][停止条件] セーフガードの誤検知を「議論すること」自体が新たな誤検知の引き金になり、ユーザーが繰り返しロックアウトされた** — https://github.com/anthropics/claude-code/issues/84821
  - **何が起きたか**: Cowork上でC++の正当な作業中にサイバー系セーフガードの誤検知を受け、その原因をgrepで調査・議論しようとする行為自体が新たな誤検知の引き金となり、8/5に25分で4回、8/7には4分で5回ブロックが発生しセッションが使用不能に。同一ユーザー・同一機器で同じgrep操作を新規セッションで行うとゼロ件だったことから、蓄積された「セーフガードについての会話」自体が分類器を発火させていたと確認された。（2026-08-07報告、Issue open）
  - **なぜ注目されているか**: 停止条件の議論は普通「タスクが終わらないループ」を想定するが、これは逆に「安全装置自体が自己参照的にループする」パターン。しかもフィードバック導線（"Send feedback"）が、そのフィードバック行為自体で次の誤検知を誘発する設計上の罠になっていた点が新しい。
  - **自分の設計への示唆**: hookやガードレールを自作する際、「ガードレールについてのメタな会話」を通常の会話と同列に扱うと誤検知の自己増幅ループを生みかねない。出題の自動検証ループでも、検証AIに却下理由を延々議論させると同種の罠にはまりうる——却下理由は次のプロンプトに短く渡すだけに留め、メタ議論を蓄積させない設計にする。
