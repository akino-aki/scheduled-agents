- **[実践][停止条件] クラウドセッションの自己リスケジュール型チェックインループが上限なしに回り続け、$250クレジットの28時間で$132・29回発火** — https://github.com/anthropics/claude-code/issues/97518
  - **何が起きたか**: 2026-09-25にクラウドセッションクレジット$250を購入したユーザーが、セッションに自分宛ての1回限りチェックインを予約させたところ、各実行が「やることがなければ黙って次を再予約する」形で無期限ループ化。約61分間隔(1時間のプロンプトキャッシュTTLをわずかに超える間隔)で29回発火しほぼ全て「実行内容なし」のまま、約28時間で$132(52.8%)を消費した。(2026-09-26報告、Claude Code on the web、Issue open)
  - **なぜ注目されているか**: 「完了を待つあいだ自分でチェックインを再予約し、何もなければ黙って再武装する」という自己リスケジュールパターンは、バックグラウンド完了待ちの定石として公式のツール説明文自体が推奨している設計そのものである。今回のIssueは、まさにその推奨パターンに実行回数上限・コスト表示・キャッシュTTLへの配慮のいずれも組み込まれていないと、実際の消費額付きで示した。
  - **自分の設計への示唆**: 自作routineやスキルでバックグラウンド作業の完了待ちに「一定時間後に自分で再チェックする」自己リスケジュール(ScheduleWakeup等)を使う設計は、上限が無いと無限に回り続けコストが積み上がると知っておく。自分で予約するチェックインには必ず最大実行回数か有効期限を明示し、間隔が1時間のキャッシュTTLの節目を跨がないようにする。

- **[実践][停止条件] CronCreate/ScheduleWakeupのスケジュールが要求周期を無視してターン直後に再発火・加速、1日で最大3,058回・9.8Bトークン** — https://github.com/anthropics/claude-code/issues/96215
  - **何が起きたか**: 毎時6回のcron設定や「5分cron＋`/loop 5m`」の設定が、ある時点から要求周期を外れて加速し、1セッションは2026-09-21に2,821回、別セッションは3,058回(うち456回はScheduleWakeup自身の呼び出し)のティックプロンプトを受信。多くが直前のアシスタントターン終了から0.15〜0.3秒後に到着し、2セッション合計で約16,000回のモデル呼び出し・9.8Bトークン(ほぼ全てキャッシュ読み込み)を1日で消費した。(2026-09-23報告、v2.1.274/v2.1.276、Issue open、has repro)
  - **なぜ注目されているか**: 09-25付ダイジェストで扱った「`/loop`の配信失敗時ウェイクアップが1秒間隔で再発火する」不具合(v2.1.281で修正済み)とは別に、今回は配信失敗ではなく正常配信されたはずのターン直後に、要求したcron境界を無視して再発火するという、CronCreate/ScheduleWakeupという定期実行の基盤そのものの周期制御が壊れていた実例が、再現可能なセッションID付きで新たに示された。
  - **自分の設計への示唆**: 自作routineでCronCreateやScheduleWakeupを使い定期実行を組む場合、現状は要求した周期が守られず突然加速することがあると知っておく。自分のroutineが実際どの間隔で発火しているかをログで定期的に確認し、想定より明らかに頻発している場合は`stop: true`で止めて再設定する運用を入れておく。

- **[実装] Routineが発火したクラウドセッションにリポジトリが一切チェックアウトされない——`create_trigger`にソース指定手段が無くGitHub Actionsのcron代替として使えない** — https://github.com/anthropics/claude-code/issues/97480
  - **何が起きたか**: GitHub Actionsのcronが3回連続で失効したためClaude CodeのRoutineをスケジュール実行のバックアップにしようとしたところ、Routineが発火させたセッションは`sources`が空配列のままリポジトリが一切チェックアウトされず、GitHub用MCPコネクタも使えない状態で起動した。対話的に作る`create_session`は`source_url`でリポジトリを指定できるのに対し、`create_trigger`には同等のソース指定パラメータが無く、回避策も無い。(2026-09-26報告、area:routines/area:mcp、Issue open)
  - **なぜ注目されているか**: 今回は、この日次ダイジェストのセッション自身が使っているスケジュール実行(Routine)の最も基本的な前提——「対話セッションと同じ環境で起動する」——が崩れている実例で、報告者はGitHub Actions cronの信頼性の穴を埋める代替としてRoutineを使おうとして初めてこれに気づいたと明記している。
  - **自分の設計への示唆**: 出題生成→検証→公開をRoutineで全自動化する設計は、`create_trigger`経由で起動するセッションには現状リポジトリが自動チェックアウトされないと知っておく。当面はセッション冒頭で明示的に`git clone`/`checkout`する手順をプロンプト側に入れておくか、対話的に作成したセッションのスケジュール実行機能に限定して運用する。
