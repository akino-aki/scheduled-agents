# 2026-09-23

- **[実装] Workflowのfan-out既定値が1週間で3段階に変更——`/goal`とDynamic Workflowsは上限到達時に打ち切らず一時停止・自動再開へ、Proプランの既定サイズは"small"へ縮小、一方で並列上限を256まで自分で引き上げる新環境変数も追加** — https://code.claude.com/docs/en/changelog
  - **何が起きたか**: v2.1.271(09-14)で`/goal`が利用上限到達時にリトライで潰れず理由を示して一時停止・上限リセット後に自動再開するよう変更され、Dynamic Workflowsも対象エージェントをドロップせずPauseするよう改善。v2.1.280(09-22)ではProプランの既定Dynamic Workflowサイズが"small"に縮小され、mediumの目安も15体→10体へ引き下げられた一方、`CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS`(1〜256)という新しい環境変数で並列上限を自分で引き上げられるようにもなった。(公式changelog記載、09-14〜09-22の3リリース)
  - **なぜ注目されているか**: 09-16〜09-22付ダイジェストで繰り返し扱ってきた「fan-outが予算を見ずに暴走する」系統(#94577, #94770, #95600, #94911, #95816)に対し、この1週間で公式側が既定値の引き下げと一時停止化という形で具体的に動いた。ただし上限そのものを外せる環境変数も同時に増えており、「既定は控えめに、必要なら自分で外せる」という設計方針に変わった。
  - **自分の設計への示唆**: 出題生成・検証のWorkflowをこれまで既定設定で回していたなら、v2.1.280以降は何もしなくてもfan-out規模が下がり暴走しにくくなる可能性がある。ただし`CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS`を安易に上げると従来通りの暴走リスクに戻るので、この変数を触るのは検証件数の見積もりを自分で出せるようになってからにする。

- **[実践][停止条件] Dynamic Workflowが購入直後の$200クレジットを2時間弱で使い切り、検証エージェントの約6割は実行すらされずに課金——週次上限は追加クレジット購入後も外れないまま** — https://github.com/anthropics/claude-code/issues/95993
  - **何が起きたか**: 週次利用上限に達したユーザーが案内通り$200の追加クレジットを購入したが上限表示は消えず、その状態で文書検証用のDynamic Workflowを起動したところ1時間50分・22分・2秒の3回の実行で$200を使い切り、コスト警告は一切出ないまま検証エージェントの約6割が実際には走らずに終了(完了済み分の結果も中断時に破棄)。(2026-09-22報告、v2.1.278・Windows、Issue open)
  - **なぜ注目されているか**: 09-20付ダイジェストで扱った「予算を見せずに5時間枠を100%消費」系統(#95600)の2日後に、今度は追加購入したクレジットまでもが同じ穴(fan-out前の見積もり・確認なし)に飲み込まれ、しかも実行されなかった分まで課金され結果も捨てられるという、対症療法(追加課金)がそのまま同じ設計の欠落にぶつかった実例。
  - **自分の設計への示唆**: 出題生成・検証のWorkflowで予算超過に備えて追加クレジットを買っても、fan-out前の見積もり確認機構が無い限り同じ速度で溶けると知っておく。検証件数×検証役数の見積もりを自分で事前計算し、Workflow起動前にその概算を出力・確認するステップを自分のスクリプト側に必ず挟む。

- **[実践][実装] バックグラウンドAgentを`TaskStop`で止めても、それが生んだ子Agentは止まらず30分間176回のツール呼び出しを継続——どの子か分からないまま許可プロンプトだけが届き続けた** — https://github.com/anthropics/claude-code/issues/95138
  - **何が起きたか**: バックグラウンドで起動した親Agentを`TaskStop`で停止したが、親が生成していた子Agentは停止対象に含まれず29分後に発覚するまで動き続け、30分間で176回のツール呼び出し(WebFetch 72・WebSearch 59・Bash 42など、同じ2.6MBのPDFを5回重複ダウンロード)を実行、その間ユーザーには「どのAgentからか分からない」許可プロンプトだけが届き続けた。(2026-09-17報告、Claude Code Desktop 2.110.0、Issue open)
  - **なぜ注目されているか**: 09-21付ダイジェストで扱った「通知が同一タスクIDに何度も重複発火する」系統(#95742)とは逆方向に、今回は停止操作そのものが子Agentへ伝播しないという、`TaskStop`の最も基本的な契約(止めたら止まる)が親子関係のあるAgentでは成立していないと具体的なツール呼び出し内訳付きで示された。
  - **自分の設計への示唆**: 出題生成・検証をバックグラウンドAgentの親子構成(例:生成役が検証役を追加で起動する)で組む設計は、親を`TaskStop`しても子が生き残り作業とAPI呼び出しを続けうると知っておく。`ListAgents`で親子関係を都度確認し、親を止めた後は子の存在も自分で確認して個別に止める運用を徹底する。
