# 2026-09-09

- **[実装] Claude Code v2.1.265 — Workflowのresumeで「コンテナ再起動によりrun journalが無い」場合、全エージェント再実行ではなく明確なエラーで失敗するように修正** — https://github.com/anthropics/claude-code/releases/tag/v2.1.265
  - **何が起きたか**: v2.1.265(2026-09-08公開)で、Workflow実行をコンテナ再起動後に`resumeFromRunId`で再開する際、run journalが見つからない場合に以前は全エージェントを最初から再実行していたが、明確なエラーで失敗するよう修正された。同リリースでは`/workflows`のagent detail表示改善(ツール呼び出しがrunning/failed/doneで表示、subagentのタスクリストを表示)も行われた。
  - **なぜ注目されているか**: 09-02付ダイジェストで扱った「利用上限到達でparallel()中の12/14体・約22分・200万トークン分の作業が中間成果物ごと破棄され、解除後も再実行対象になる」#91449と直接つながる修正。ただし解決したのは「journal自体が無い場合に何が起きるか」という一部分であり、"silent re-run"を"clear error"に変えただけで、journalがあるのに一部エージェントの成果が消える根本問題(#91449)自体が直っていない点には注意が要る。
  - **自分の設計への示唆**: Workflowのparallel()を長時間サブエージェントで組む設計は、v2.1.265以降なら「resumeしたら気づかぬうちに全部やり直しになっていた」という最悪の無音失敗は減ると見込める。ただし「run journalがあれば必ず全成果物が復元される」ことまでは保証されていないため、各サブエージェントに前回の途中経過をディスク上から拾って続きから再開させる自前ロジック(09-02付の教訓)は引き続き必要。

- **[実践][停止条件] 6体の並列バックグラウンドエージェント起動中に送った3件の軌道修正メッセージが数分間読まれず、`Interrupt`を使うと今度は起動途中の5体未満のエージェントとbashプロセスごと強制終了される——非破壊的にタスクを差し込む手段が存在しない** — https://github.com/anthropics/claude-code/issues/92899
  - **何が起きたか**: 1ターンで6体の並列バックグラウンドエージェントを起動した直後、最初のエージェント起動中に3件の修正メッセージを連続送信したところ、複数のツール呼び出しをまたいで数分間読まれず元の指示のまま起動が続いた。`Interrupt`を使うと最初の1件だけは即座に届くが起動途中のエージェントとbashプロセスが巻き添えで強制終了され、残り2件のメッセージは保留のままになった。報告者は`tool_result`と同じuserメッセージに訂正テキストを追加する形での即時反映を改善案として提示している。(2026-09-08報告、v2.1.263・Claude Fable 5.1・Linux/WSL2、Issue open、再現手順あり)
  - **なぜ注目されているか**: これまでのダイジェストが扱ってきた「サブエージェントへの`SendMessage`が届かない」系統(09-02付#91242、09-05付#92134)は配送経路の不具合だったが、今回はメッセージが届くこと自体は保証されているのに「待つ(数分読まれない)」か「割り込む(実行中の作業を巻き添えで殺す)」の二択しか無く、軌道修正だけを非破壊的に差し込む手段がそもそも設計として存在しないという、一段手前の構造的な穴を具体的な再現手順付きで指摘した。
  - **自分の設計への示唆**: 出題生成・検証を複数の並列バックグラウンドエージェントで組む設計は、走り出した後の軌道修正が「待つか全部殺すか」の二択しかないと知っておく。誤った前提でエージェントを走らせてしまった場合の被害を抑えるには、軌道修正よりも「早期に安く判定を返す短いチェックポイントを挟み、そこで一旦停止させてから再指示する」設計の方が、今の`Interrupt`の挙動には合っている。

- **[実践][実装] `Agent(isolation:"worktree")`で分離されたエージェントが自分の内部から別リポジトリ向けの子Agentを生成しようとすると、明示的な`isolation`指定でもcdによる回避でも同じエラーで拒否される——worktreeへのピン留めが子への差し替えなしにそのまま継承される** — https://github.com/anthropics/claude-code/issues/92869
  - **何が起きたか**: リポジトリAに対し`Agent(isolation:"worktree")`で起動したエージェントの内部から、リポジトリBを対象とする子Agentを生成しようとしたところ、子Agentに`isolation:"worktree"`を明示指定した場合と、分離指定なしでリポジトリBへの`cd`だけを指示した場合の両方で、「a worktree-isolated agent's git operations must target its own worktree」という同一エラーで拒否された。回避策は、worktree分離されていない最上位セッションから子Agentをディスパッチすることのみ。(2026-09-08報告、area:agents、Issue open)
  - **なぜ注目されているか**: 09-07付ダイジェストで扱った「Bashへの空のtool.callフックを1つ登録しただけでworktree隔離の全Bashコマンドが拒否される」#92533とは別角度で、今回は隔離機構と無関係な操作ではなく「worktree隔離されたエージェントから別リポジトリへ委譲する」という一見自然なクロスリポジトリ・オーケストレーションのパターンそのものが、分離状態が子へそのまま継承され差し替えられないという設計により機能しないと特定された。
  - **自分の設計への示唆**: 出題生成・検証をworktree並列で組む設計自体には直接関係しないが、AWSマルチアカウント環境でリポジトリをまたいで子Agentに委譲する自律運用を考える際は、worktree隔離された階層の内側からは別リポジトリへディスパッチできないと知っておく。クロスリポジトリの委譲が要る設計は、隔離されていない最上位から一度に複数の対象リポジトリへ子Agentを出す構成にする。

- **[実践][停止条件] サブスクリプション上限到達時のクレジット自動消費の一時停止が、サブエージェント実行中に限って効かず有料クレジットが浪費される——上位モデル用に確保していた予算が下位タスクで消費される** — https://github.com/anthropics/claude-code/issues/92800
  - **何が起きたか**: サブエージェント実行中にサブスクリプションの上限に到達しても、クレジットの自動消費が一時停止する保護機構が働かず消費が継続する。報告者は低階層のサブエージェントタスクの実行によって、上位モデル用に確保しておきたいクレジットが消費されてしまうと指摘し、サブエージェントワークフロー向けの厳密なクレジット上限設定と自動停止セーフガードを要望している。(2026-09-08報告、v2.1.263・Linux/VSCode、area:cost、Issue open)
  - **なぜ注目されているか**: 09-04付ダイジェストで扱った「安いモデルへのダウングレード型の支出ガードが実は無制限で機能しない」#91682、09-07付「サブスク上限到達直後にクレジット課金へ切替わり30分で$50請求」#92508と同系統だが、今回は「サブスク上限に達したら自動消費を止める」という基本的な保護そのものが、サブエージェント実行というルートに限って抜け落ちるという、より手前の欠落を指摘している。
  - **自分の設計への示唆**: 出題生成・検証のループでサブエージェントを多用する設計は、サブスク上限到達後の自動停止をこの保護機構だけに頼らない。09-04・09-07付の教訓と同様、日次・複数日の累積消費を自前でログから確認する仕組みを持たせ、サブエージェント実行が上位モデル用の予算を食いつぶしていないかを定期的にチェックする。
