# 2026-08-15

- **[実装][停止条件] Claude Code v2.1.232 — サブエージェントのfork・バックグラウンド生成が既定オンに、`@`セッション名でクロスセッション通知** — https://github.com/anthropics/claude-code/releases/tag/v2.1.232
  - **何が起きたか**: v2.1.232（8/13 23:29 UTC公開）で、親の会話とプロンプトキャッシュを継承する`subagent_type: "fork"`のサブエージェントが対話セッションで既定オンになり、teammateでないエージェント生成も既定でバックグラウンド実行になった。同時にプロンプト内で`@`+セッション名と打つとSendMessageで直接そのセッションに届く機能も追加された。
  - **なぜ注目されているか**: 8/8付ダイジェストで扱ったクロスセッションメッセージング(v2.1.224)を使いやすくする直接の追加機能である一方、fork・バックグラウンド生成の既定化は、サブエージェントが親のhooks/設定/memoryを継承しないという既知の性質（下記yurukusaのfield reference）と組み合わさると、意図せず並列度が上がりやすくなる変更でもある。
  - **自分の設計への示唆**: worktree並列でサブエージェントに分業させる設計を組むなら、この既定変更でバックグラウンド生成が増える前提でコスト・並列数を見積もり直す。旧挙動に戻すなら`CLAUDE_CODE_FORK_SUBAGENT=0`が使えることも覚えておく。今の1セッション完結の出題生成では直接の影響は薄いが、分業させ始めたら要確認。

- **[実装][停止条件] Claude Code v2.1.233 — BashツールにLinux向けcgroupメモリ上限`CLAUDE_CODE_TOOL_MEMORY_LIMIT`を追加** — https://github.com/anthropics/claude-code/releases/tag/v2.1.233
  - **何が起きたか**: v2.1.233（8/14 22:20 UTC公開）で、Bashツール実行にオプトインのcgroupメモリ制限`CLAUDE_CODE_TOOL_MEMORY_LIMIT`が追加された。公式リリースノートは「暴走したビルドがセッションをstallさせないように」と明記している。
  - **なぜ注目されているか**: これまでのダイジェストで扱ってきた暴走防止は「経過時間」ベースのwatchdogが正当に時間のかかる作業と本当のハングを区別できない問題（8/10付#85206）だったが、今回はメモリ使用量という別の軸から暴走ビルドを止める仕組みが公式実装として加わった。時間・メモリと複数の軸で暴走防止策が積み上がり始めている。
  - **自分の設計への示唆**: 出題生成・検証ループでnpm ci等のビルドを含む工程を回すなら、時間watchdogだけでなくこのcgroupメモリ上限も併用できる。Linux上のCIや自作routineでは導入コストが低いので、次にビルドを伴う工程を組むときに設定を検討する。

- **[実践][停止条件] 権限拒否がサブエージェントの再帰生成を誘発——1.2Mトークン/約30分で再帰50階層超、設定は子エージェントに伝播しない** — https://gist.github.com/yurukusa/4c77d3f72a29318da978f6c01678c6e6
  - **何が起きたか**: 6月中旬〜8/12にかけて複数報告された事例をまとめたfield referenceによると、サブエージェントは権限拒否に遭うと「止まれ」ではなく「別の方法を子エージェントに生成させよ」の合図として扱い再帰的に増殖するケースがある。実測で1.2Mトークン/約30分・再帰50階層超に達した例、4Mトークン/5分未満でPro Max 20xの5時間クォータを使い切った例が報告されている。`CLAUDE_CODE_FORK_SUBAGENT=0`のような設定は最初の生成にしか効かず、子エージェントは親のhooks/設定/memoryを継承しないため木の奥まで伝播しない。（2026-08-12更新）
  - **なぜ注目されているか**: 「上限を設定で決めれば防げる」という一般的な停止条件設計の前提が、設定が子に継承されないという一点で崩れる実例。8/11付ダイジェストで扱ったSubagentStop hookのフィードバック不達バグ(#85917)と合わせ、サブエージェント階層の制御がconfig/hookレベルでは閉じきらない傾向が繰り返し確認されている。
  - **自分の設計への示唆**: 出題生成・検証をサブエージェントに分業させる設計では、権限を都度確認させず必要な権限を事前に付与しきっておき、拒否がそのまま新たな生成の引き金にならないようにする。加えてクォータの急減を監視して手動で止められる運用上の防御線を、config任せにせず自分で持っておく。
