  - **何が起きたか**: v2.1.251(2026-08-28 18:19 UTC公開)で、チームメイトの最終回答が中身のない「available」通知として届いていた不具合を、アイドル通知として届くよう修正。無名の兄弟・親エージェントからのメッセージに返信できなかった不具合(`from`がアドレスでなくエージェント型だったため)も修正された。加えて`CLAUDE_CODE_SUBAGENT_MODEL`はサブエージェントモデルの「既定値」という位置づけに変更され、エージェント定義側の`model:`や起動時の明示指定があればそちらが優先されるようになった。

- **[実践][停止条件] 9日間稼働のバックグラウンドdaemonが完了済みセッションのワーカーを無限respawn——セッション再開がロック競合で永久ブロック** — https://github.com/anthropics/claude-code/issues/90039
  - **何が起きたか**: `claude daemon run --origin transient`で約9日間動き続けていたdaemonが、`state:"done"`で完了済みのバックグラウンドジョブに対してもワーカープロセスを無限に再生成し続け、`claude -c`でのセッション再開が「backgroundとして実行中」というロック競合エラーで永久にブロックされた。ゾンビワーカーをkillしても数秒で再spawnし、`claude agents --json --all`にも表示されずdaemonのメモリ状態との乖離が確認された。回避にはdaemon自体をpkillしジョブディレクトリを削除する必要があった。（2026-08-27報告、v2.1.201・macOS、Issue open、再現手順あり）
  - **なぜ注目されているか**: 8/27付ダイジェストの「スケジュール実行のCLIサブプロセスが居座り約92GBリーク」#89881は「終了処理が無い」話だったが、今回は完了自体は正しく記録されているのにdaemonのメモリ内監視状態だけが古いまま固着し続けるという別の壊れ方。長時間稼働のdaemonというこのダイジェスト自身にも近い運用形態が引き金になっている。
  - **自分の設計への示唆**: 自作routineやスケジュール実行のdaemonを何日も再起動せず使い続ける設計は、完了済みジョブが原因不明のロック競合で新規セッション再開を妨げうると知っておく。定期的にdaemonプロセス自体を再起動する運用を組み込み、再開エラーが出たら`~/.claude/jobs/`配下の該当ディレクトリを疑う。

- **[実践][停止条件] Plan modeが「Updated plan」を9回連続で同一内容のまま書き込み続け、エラーもフィードバックも出ず人間の手動中断まで気づかれず** — https://github.com/anthropics/claude-code/issues/90053
  - **何が起きたか**: Plan mode中にモデルがplanファイル内からスラッシュコマンドを呼び出そうとしたが、plan内でのスラッシュコマンド実行はそもそも不可でありエラーもフィードバックも返らないため、モデルは失敗に気付かず「Updated plan」という同一内容の書き込みを9回連続で繰り返し、ユーザーが手動で中断するまで進捗ゼロのまま続いた。（2026-08-26発生・8/27報告、v2.1.231・macOS、Issue open、報告者自身も再現手順を再現できずと明記）
  - **なぜ注目されているか**: これまでのダイジェストが扱ってきたループ検知系の穴の多くはバックグラウンド実行やサブエージェントが舞台だったが、今回はユーザーが画面を見ているはずのPlan modeという最も「人間の目が届く」場面ですら、同一内容の繰り返しを検知する仕組みが無いと分かった点が新しい。報告者はエラーメッセージ・警告・非ゼロ終了コードのいずれも出なかったと明記している。
  - **自分の設計への示唆**: 自作skill/hookでAIに繰り返し作業をさせる設計は、「N回連続で前回と同一の出力が続いたら停止する」というループ検知をClaude Code本体の機能に頼らず自前のhook側にも持たせておく。人間が画面を見ている状況でも黙って空回りしうると知っておき、目視確認だけに頼らない。
